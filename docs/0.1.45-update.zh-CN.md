# 0.1.45 更新检查

自动检查默认开启，并保留既有关闭设置。每次启动在短暂延迟后检查一次；上次运行的检查时间不会阻止这次启动检查。应用启动时处于锁定状态，则在解锁后执行一次。运行期间每 30 分钟触发检查，每次自动尝试开始时重新计时；上一次自动尝试不足 30 分钟时不会重复请求，系统时间回拨也不会造成频繁请求。

启动检查和定时检查遵守相同的自动检查开关，原先关闭的设置仍然关闭。锁定、配置迁移、下载、更新准备或重启确认期间不会发起自动检查；跳过的定时检查等待后续机会。自动检查不会覆盖已校验的待安装下载；应用锁本身仍会取消进行中的更新任务并清理暂存下载。发现可用更新后仍可在后续定时检查中发现更新的版本，检查期间保留已有更新提示。相同版本的自动通知会去重，不会自动下载或安装，直到用户选择更新。

GitHub 返回 429，或返回带限流信息的 403 时，程序记录重试时间；该等待期也适用于手动检查和下一次启动。支持 `Retry-After` 或 GitHub 的限流重置时间，缺少有效时间时默认等待 60 秒，单次等待最长 24 小时。服务限流期间不发起新的检查。

Windows 发布流程要求每个版本同时提供 `FrogShell-<版本>-portable.exe`、`FrogShell-<版本>-setup.exe` 和包含两个文件的 `SHA256SUMS`。安装版封装相同的单文件便携程序，运行时沿用现有更新引擎。更新检测按平台和架构匹配精确的便携版文件名，优先使用 Release 资源自身的 SHA-256 摘要，否则从校验清单中查找该文件名；不会把 setup 作为自动更新载荷。目录运行、其他平台或缺少可验证资源时使用手动更新。安装与卸载边界见 [安装包说明](0.1.45-installer.zh-CN.md)。
