# RabbitShell 浮窗与文件图标设计

## 0.1.20 本地拖入增补

本地文件拖入与Windows远端拖出分别处理。本地拖入仅复制真实本地URL，统一目标解析驱动整行边框/目标路径预览和实际投放；文件行用父目录、空白用已提交根，链接/草稿/未知拒绝，不悄悄改投根。右键上传锁定菜单打开时路径。离开/投放/隐藏/目标删除清预览，不改变选择。Windows原生拖出及编辑页签反馈沿用0.1.19，私有SFTP回归通过，仍不宣称真实Explorer或混合DPI已验收。见[0.1.20记录](RabbitShell-0.1.20验证记录.md)。

## 0.1.19 增补

编辑页签拖影使用其真实文件图标；窗外反馈是小窗口＋向外箭头，应用内无效目标仍禁止，内部合法目标保持Move。Windows Qt6.8.3公开QDrag::setDragCursor(IgnoreAction)进入QWindowsOleDropSource::GiveFeedback的cacheKey/createCursors/SetCursor路径；WH_GETMESSAGE只观察消息，用QCursor::pos逻辑坐标更新反馈，不吞消息。原DragReleaseGuard仍要求明确鼠标释放且未取消才浮窗，不把IgnoreAction单独视为成功。cursor随应用倍率与DPR绘制。

远端普通文件拖出使用同一Seti图标生成小拖影，交给Windows IDragSourceHelper，实际InitializeFromBitmap成功由COM测试验证。该helper使用HGLOBAL和IStream私有格式，数据对象有界复制并遵循fRelease。协议、暂存和未验收范围见[0.1.19记录](RabbitShell-0.1.19验证记录.md)。以下保留0.1.9历史设计。

## 1. 独立窗口

删除独立终端、独立文件编辑窗口中，原生标题栏下重复显示服务器名称、账号和地址的整条信息栏；不能只隐藏文字而保留同高的空白区域。

服务器身份继续显示在原生窗口标题中，并包含当前终端名或文件路径。终端内容直接从客户区顶部开始；文件编辑窗口保留现有文件路径、保存动作和底部编码信息。

收回工作区功能保留，通过现有右键菜单提供；编辑窗口在已有工具行安置纯图标动作，不为收回按钮单独新增横栏。不为本轮删栏增加抢占终端输入的快捷键。关闭、收回和隐藏仍是不同操作：收回移动原有对象，不关闭 SSH 通道，不重新打开文件，不丢失草稿、撤销、选区或滚动位置。未保存文件关闭保护保持。

## 3. 图标匹配与覆盖

采用集中式文件图标提供器，以文件名和已知文件类型匹配实际 Seti 字形。主题中的完整文件名规则优先，其次匹配最长复合后缀，再使用语言类型规则，最后回退通用文件图标。补充 VSCode 内置语言清单中的文件名、后缀和适用的文件名模式，避免只有语言 ID 的 JS、TS 等常见类型丢失图标。

应覆盖：TS／JS／TSX／JSX、JSON、HTML／CSS、Python、C／C++、Shell／PowerShell、YAML／INI／配置、Markdown、Dockerfile、Makefile／CMakeLists.txt、README、Git 相关文件，以及主题已有的图片、音频、视频、压缩包、证书等关联。未知文件使用通用图标，不根据名称猜测文件内容。

本轮按文件名匹配，不额外读取远端文件以识别类型，不运行远端命令。用户安装的其他扩展、语言服务、手动选择语言及内容检测可能影响 VSCode 的结果，因此不承诺所有第三方扩展场景逐项一致。Seti 未定义目录图标时保留统一目录图标及展开状态，不能将目录误用为文件图标。

接入位置包括资源管理树、普通与分屏编辑页签、文件浮窗的窗口图标及已有文件路径行。同一路径采用一致图标；文件重命名或目录重命名后的路径变化同步更新。页签拖动、分屏、浮出与收回保留图标。

## 4. 外观与资源

使用 Seti 原始字形与颜色，不用普通字体写 TS／JS 冒充文件图标。暗色和浅色分别采用主题对应映射，在选中、失焦与高 DPI 状态下仍能识别。必要的通用回退图标以可读性为准。

只打包需要的图标资源和关联表。图标源转换属于开发步骤，运行时只依赖现有 Qt 原生绘制能力；不加载 VSCode、不引入 WebEngine，不读取用户 VSCode 配置，也不新增远端依赖。本轮将 Seti 字体轮廓转换为 Qt 可绘制的矢量路径，运行时无需安装图标字体；字形与映射集中加载一次，缓存按有限图标种类及必要尺寸组织，不能按所有历史路径无限增长。

主题切换只更新图标绘制与必要视图，不重建编辑器／终端。字形资源异常时使用可读回退，不能显示缺字方框。

## 5. 验收重点

- 两类浮窗均无重复信息栏或残留留白，原生标题仍有服务器归属；收回、关闭和未保存保护可用。
- 截图中的 TS／JS 图标与 Seti 对应，混合文件树、分屏、浮窗和主题切换保持一致；重命名后更新类型图标。
- 校验完整文件名、复合后缀、无扩展名、点文件、未知类型、目录和非 ASCII 文件名；不能让文件类型匹配改变真实路径大小写。
- 在不读取外部 VSCode 资源的交付包中验证图标可渲染；两主题离屏截图检查尺寸与对齐，明确离屏与真实桌面 DPI 验证的边界。
- 资源加载和缓存具备明确上限；本轮不以图标功能为由增加后台采样、远端请求或持久化每个文件路径。
