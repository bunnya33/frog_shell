# 0.1.41 端口占用与启用恢复

## 实施与验收计划

实际 bind 与 listen 是监听成功的必要条件。Windows 监听 socket 在绑定前设置 SO_EXCLUSIVEADDRUSE，绑定后持有同一个 descriptor，使用 IP Helper 的本机 TCP 监听快照核对已有地址范围重叠，再 listen 并交给 Qt 接收连接；不连接探测、不启动 netstat、不释放后重绑。补充快照是因为 Windows 允许已有 wildcard/reuse listener 与后来的具体地址独占 socket 同时 bind/listen，单凭独占标志仍可能误报成功。只有 SSH 认证与真实监听均就绪、快照核实成功才进入 running。

只阻止同地址或 wildcard 覆盖，127.0.0.1 和 127.0.0.2 的同号端口仍合法。IPv6 显式 IPv6-only，保留地址 scope；Windows 双栈 wildcard 的 IPv4 shadow listener 也由 IPv4 快照覆盖。快照有次数与内存上限，失败显示“无法核实系统监听地址”而不假报占用。绑定错误包含地址、端口和系统原因；无法承诺阻止此后其它程序使用 Windows 的特殊 reuse 行为抢占。

沿用 TunnelRule::autoStart：首次成功启用才记住 true，手动停用记住 false；断开、退出及暂时失败不改持久意图。恢复使用现有主会话 connected 入口，一次连接仅恢复一次；健康规则不重复启动，正在释放的服务待 idle 后再启动。失败规则不无限重试，不强制切换端口页；用户可在失败/停止规则的菜单中取消自动恢复。高级设置不再提供与开关冲突的第二个启用开关。

手动启动失败使用统一 AppMessageBox；自动恢复失败按本批合并提示一次，同时保留行状态/tooltip，不循环重试或反复弹窗。保存失败明确显示“未保存”及下次恢复行为，不能暗示已记住。异步 running 回调需核对当前服务、提交规则、用户意图、停止/关闭/锁定状态，旧回调不能重新记住已停用的规则。

验证使用临时配置和私有 loopback SSH fixture：Windows 普通/reuse/wildcard/独占监听、同址冲突与不同地址合法监听、释放后重试、停止重启、正常流量；成功记住、失败不误记、手动关闭、重开与重连恢复、单条失败隔离、profile 隔离、保存失败及异步竞态。记录红绿结果与实际暗浅提示截图。main-*、旧版本包和证据保持只读；配置路径/日志设置由独立 agent 实施，本写集不触及。
