# 0.1.41 服务器时钟工作区接线

工作区 footer 在右侧面板与任务按钮之前显示服务器时间。它使用现有 `serviceSession(..., Session::Mode::Commands)` 工厂创建独立命令连接，继承凭据、主机身份验证与关闭回收机制。主 Files/PTY Session 不执行时钟命令，`serviceCommand` 的模式及无 PTY 限制保留。

可见且激活的工作区在主连接成功后启动一次采样；显示秒数用本机单调时间推算，约 60 秒只读校准。隐藏、切换工作区、应用锁、断线及关闭会使显示过期并关闭编辑面板；主断线或身份撤销时 detach/stop 专用连接，旧回调不能重新显示为当前时间。未同步状态使用“服务器时间 —”，不以本机时间替代。

凭据 repository 的 revision 递增现在同步发出 `invalidated(id)`，工作区立即撤销时钟写入许可并停止连接。覆盖显式 invalidate、更新与删除；异步凭据处理 pending 期间不重建连接，idle 后按当前身份恢复。credential/services generation 变化及认证拒绝同样撤销。后台在只读 preflight 后核对原子许可与应用锁 epoch；已经发出的远端写命令无法撤回，结果未知只做只读复查，不自动重放写操作。

日期时间修改只有用户点击并确认后提交，提示按服务器时区解释以及 root/现有免密 sudo 的权限方式。不关闭自动校时，不安装工具。具体命令、输出与超时边界由独立 serverclock 模块实现及验证。

`tests/run_clock_integration.py` 配合 `ssh_fixture.py --clock-fixture` 通过真实 Workspace 入口验证专用命令连接与主 PTY 并存。fixture 只识别固定采样标记并返回合成日期，绝不执行 date/timedatectl/sudo。审计按 SSH transport 区分时钟与 PTY，并要求没有写时钟请求；工作区单元回归另覆盖身份同步撤销。所有测试只用临时配置与私有 loopback，不触碰用户服务器或本机系统时钟。
