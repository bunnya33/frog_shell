# FrogShell 关于与更新接线

帮助 → 关于 FrogShell 显示应用版本、Qt 版本、平台与架构，发布说明始终作为纯文本显示。关于窗口只是一份视图；关闭窗口不会取消后台下载，重新打开仍显示同一更新任务。

设置 → 更新保存公共 GitHub 的用户/组织与仓库名称，不接收任意 API URL。默认仓库为空、自动检查关闭；未配置时不联网。开启后最多每 24 小时自动检查一次，手动检查不受此节流限制，HTTP 限流仍生效。首次启动后尝试检查，应用级定时器每小时再次交给核心判断节流，长期驻留托盘也有效；禁用、锁定或未配置时不发请求。自动检查不自动下载、不安装、不弹出模态通知。

Windows x64 单 EXE 启动器先过滤所有继承的 `RABBITSHELL_PORTABLE_*` 字段，再根据自身打开文件、流式 SHA-256、进程创建时间和文件身份写入 origin。开发 runtime 覆盖不设置 origin。下载核心和安装核心再次校验来源、摘要、大小、实际父子进程关系和目标身份；不依赖传入环境变量直接替换程序。其它运行方式明确显示手动更新，可打开发布页或已校验文件所在目录。

安装计划由应用级 UpdateController 持有，与关于窗口生命周期无关。只有点击“重启更新”才后台准备私有计划；取消退出、保存失败、锁定或身份过期会撤销未接手计划。正常退出成功后，main 取走 PreparedInstall，在窗口和 AppLock 释放后再启动同一 runtime 的 QCore helper。配置迁移与更新重启互斥。

最早内部入口仅识别精确 `--internal-install-update <plan>`，不创建 QWidget、不访问普通设置和单实例。新程序的 receipt 参数仍进入完整正常启动；主窗口或 AppLock 启动画面建立后才确认启动，未解锁也不因此强杀或回滚。只有 receipt complete 表示安装成功。receipt 路径与 token 在准备后、退出确认前持久化；退出取消恢复先前记录，后续手动启动也能显示失败、回滚或需手动恢复状态。恢复备份由核心验证后处理，UI 不自行删除。

下载文件用共享所有权覆盖后台 prepare 读取期间；取消后等待读句柄释放才回收原文件。外部占用导致删除失败时保留有限清理记录，不把记录转换为任意路径自动删除。日志继续服从默认关闭和用户选择目录。

## GitHub 发布约定

`.github/workflows/release-windows.yml` 将稳定 tag `vX.Y.Z` 与 CMake 版本精确比对，构建 Windows x64，生成目录清单和完整 `FrogShell-X.Y.Z-portable.exe`，运行隔离 smoke 后生成 `SHA256SUMS`。摘要清单使用 `64位小写hex + 两空格 + 精确资源名`；下载核心优先采用 GitHub asset.digest，否则查验此固定清单。不使用独立“最新版本”文本文件。

推送稳定 tag 可发布；手动 workflow 默认只产出 CI artifact，必须显式勾选 publish 才发布到已有 tag。不会覆盖已有 Release 资源。仓库尚未指定，本次仅提交本地 workflow 和说明，没有创建远端仓库、tag 或 Release，也未访问真实发布源。

## 控制器测试接口

`ui/updatecontroller.h` 构造参数是 runtime Config、PortableOrigin、私有 stagingBase、QObject parent 和可选 QNetworkAccessManager。注入 transport 只用于构造依赖；生产没有 HTTP/任意 URL 开关。公开 `configureSource/check/download/cancel/requestRestart`、`state/statusText/ready/restartPending` 与 `changed/restartRequested` 支持隔离控件测试。

About 对象：`aboutFrogShellDialog`、`aboutCheckUpdate`、`aboutDownloadUpdate`、`aboutRestartUpdate`、`aboutCancelUpdate`、`aboutUpdateProgress`、`aboutReleaseNotes`、`aboutInstallStatus`。设置：`updateGitHubOwner`、`updateGitHubRepo`、`updateAutomaticCheck`、`saveUpdateSettings`。
