# FrogShell 0.1.51 验证记录

## 范围和原因

0.1.49 修复编辑时自动选中搜索结果后，仍在每次文档变化时清空匹配列表和绘制，造成约 100ms 防抖时间加后台查找耗时的空白间隔。另一个问题是后台完成时按当前光标重新决定橙色匹配项，使未修改的当前项改变颜色。

此次为匹配项保留随文档编辑移动的字节锚点，修改时仅剔除被触及的匹配，后台结果完成后一次性替换。通过原匹配的起止位置保留当前项身份。Scintilla 继续管理文字、选择和绘制，没有引入额外文本副本或远端工具。

## 验收方法

在修复前的代码上运行新增回归：两种主题下无关输入清空实际引擎高亮、编辑单项使其余高亮消失、前面新增匹配导致当前项跳转，共 4 项失败，确认与用户反馈一致。

新增回归同时检查防抖等待期间和后台搜索运行期间的原生 indicator、匹配计数与渲染截图，避免只验证最终恢复后的状态。覆盖中文、Emoji、跨行插入、撤销重做、匹配边界、全字匹配和正则前瞻上下文变化，检查光标及用户选区不被抢走。深浅主题分别检查黄色及橙色的实际绘制。

补充批量替换回归：512 项匹配的全部替换，修复前累计处理 261633 项装饰；批量操作开始时一次性失效整组匹配后，修改通知中累计处理的剩余匹配为 0。一次本机离屏测量从 326ms 降至 26ms，这只是该样本的操作耗时，不代表所有文件的固定提升比例。测试同时检查替换结果和单次撤销恢复。

本地 6 组回归共 177 项通过，0 失败、0 跳过：编辑器高亮/选区 27、编辑器引擎 8、高级搜索 20、语法诊断 35、编辑分组 34、外观 53。逐项结果和截图保存在 `test-results/0.1.51/`。Windows Release 工作流从同一标签构建便携版与安装版，执行隔离启动及安装/卸载检查；发布后核对公开附件摘要和版本。

## 边界

被编辑的匹配项及受全字/正则上下文变化影响的项按新内容更新，不承诺保持已失效的高亮。GUI 验证使用 Qt 隔离设置和离屏渲染，没有操作用户的服务器或替换正在运行的程序。
