# 编辑分组、面板边界与图标按钮

可复用的分组、Frame、图标与生命周期规则见 [Qt 桌面应用通用开发规范](qt-desktop-guidelines.zh-CN.md)；本文保留本项目启用的能力、具体交互与验收依据。

2026-11-03。依据用户反馈和三张参考截图制定；本文是设计约定，实际完成及测试结果另记于实现记录。

## 编辑分组

编辑区域使用动态分割树，叶节点为页签组，内部节点表示左右或上下布局。支持三组及更多组。依据用户补充的 VSCode 同排三列截图，横向分屏始终沿左右方向增加列：两列、三列、四列都在同一排，不能因组数增加自动改成两排或网格。布局不限定为两个固定容器。

- 连续执行左右分屏时，在现有同向分割容器中插入相邻列，合理分配列宽；不得自动交替横竖方向。新增列的落点预览与最终位置保持一致。
- 只有用户明确执行向上／向下分屏或拖至对应边缘，才创建上下布局；默认分屏动作、演示示例和验收截图均以同排多列为基准。

- 页签移空、关闭最后一个页签或将最后一页移到浮窗时，移除该空组，并折叠只有一个子节点的分割容器；任一方向的空组都遵守此规则。
- 整个编辑区没有内容时保留一个空编辑区域。单页不通过复制内容来制造分屏；拖动唯一页签到自身边缘不产生空白分区。
- 新文件进入活动编辑组；点击或聚焦组内内容更新活动组。合并操作将全部组内容归入活动组，不丢失页签。
- 编辑器和进程页参与统一页签布局管理，已有进程页直接定位。0.1.8 终端禁止进入 EditorArea，通用迁移入口同样拒绝；终端组与独立浮窗由终端区域管理。
- 页签迁移复用原控件，保留草稿、撤销记录和滚动位置。窗口浮出与收回不重新载入内容。
- 分割器收缩与组删除在迁移完成后处理，不能因移除信号发送者而破坏当前拖拽或关闭操作。普通组间移动保留现有布局比例。

### 0.1.6 页签同行操作

删除编辑区上方整条 `editorHead`，不保留“文件编辑”占位标题；每个组的页签栏右侧放分屏和合并两个图标。分屏主体默认向右，独立可见箭头展开向右／向下菜单；图标 20px，分屏点击区 42×30px，合并 30×30px。corner 区域与页签行同高，按钮垂直居中；长页签省略并由原生页签滚动处理，不能覆盖工具区。终端自己的 `terminalHead` 沿用。

按钮和菜单动作均归所属组；点击前活动组即使在别处，也先激活点击组再执行分屏／合并。单页分屏禁用，全部合并归入点击组。菜单期间保留组交互保护，动作使用 QPointer 防止来源销毁；关闭、拖放与组清理的原有保护继续生效。拖放插入区域必须落在实际 tabBar 矩形内，corner 按钮区拒绝拖放并清预览。

Qt 页签按钮替换只会隐藏旧控件。所有自定义关闭按钮替换／管理页移除按钮的路径均显式延后销毁旧控件，并处理原生左右两侧的关闭按钮。文档、撤销栈、高亮器继续由现有 QObject 所属关系与 closePage／DeferredDelete 回收。

### 0.1.7 终端面板

底部终端面板的拆分固定为左右同排，删除方向选择框；这不改变编辑器页签区域已有的显式上下分屏。最大化按钮只隐藏右侧编辑区并扩展终端面板，保留原编辑组、文档、终端、进程页及浮窗归属；还原时恢复原终端高度。最大化时隐藏终端面板先恢复编辑区，左侧导航和页脚始终保留，不使用操作系统全屏。移动终端继续复用原控件和 PTY，最终几何仍通过既有 resize 合并机制传递。

### 0.1.8 终端与编辑区域归属

终端菜单移除“移到编辑区域”及颜色动作；保留重命名、拆分、独立组和独立浮窗。终端浮窗返回按钮或关闭浮窗收回原终端组，保持同一个 PTY／Terminal／ID；不向编辑页签插入终端，不改变编辑分屏布局。单终端垃圾桶直接关闭，不影响文件未保存保护。总栏当前名、管理选中行操作及四角最大化规则以 [0.1.8 验证记录](RabbitShell-0.1.8验证记录.md) 为准。

## 拖拽交互

达到系统拖动阈值后显示跟随鼠标的小页签，包含当前文件名；页面在放置成功前保留在原组。

| 落点 | 反馈与结果 |
| --- | --- |
| 同组或其他组的页签栏 | 显示插入位置，放下后调整顺序或移入该组 |
| 目标内容区中央 | 显示合并预览，放下后加入该组 |
| 目标内容区左／右／上／下边缘 | 显示对应半区的半透明预览框，放下后在此方向新建组 |
| 主窗口外 | 明确拖出并松手后成为同服务器的独立原生窗口 |
| 侧栏、无效区域或其他服务器工作区 | 拒绝移动，保留原状态 |
| Esc、取消或来源失效 | 清除预览，原页签和内容保持不变，不创建浮窗 |

预览不截获鼠标，不改变正文布局，不使用常驻刷新定时器。结束、取消、离开目标或目标销毁时清理预览。工作区内部拖拽验证来源，不因外部 MIME 内容接受任意对象或跨服务器迁移。

## 面板边界

两套主题都应能直接识别活动栏、资源／服务器侧栏、编辑组、终端、传输面板和底栏的区域边界。主要区块使用可辨的单条细边线，辅助背景差异表达层次；不能仅靠留白或近乎相同的底色区分。

主题集中维护主要面板边线、卡片边线、内部分隔线、活动组标记和拖放预览色。主要边界参考 1 逻辑像素，分割手柄提供足够命中范围和悬停反馈；共享边线由一侧负责，避免多重描边。卡片有独立外框，内部标签及布局控件不继承容器边框。footer 顶部必须有持续可见的分隔。

边框的可辨性以 Dracula、GitHub Light 的实际渲染验收，不能仅检查代码里是否设置了 border。保留系统原生标题栏、圆角和窗口阴影，不为这次分区修改引入整窗透明或重复窗口外框。

## 图标按钮

活动栏和工具栏的图标型操作采用统一矢量图标，不用字符或 Emoji 充当工具图标。图标按钮不再并排拼接小符号和文字，悬停显示中文操作名称；已存在的快捷键可附于提示中，同时提供无障碍名称。

| 位置 | 图标参考尺寸 | 点击区域参考尺寸 |
| --- | --- | --- |
| 活动栏 | 24 逻辑像素 | 40～44 逻辑像素 |
| 工具栏 | 18～20 逻辑像素 | 28～32 逻辑像素 |
| 页签关闭 | 16 逻辑像素 | 22～24 逻辑像素 |

图标覆盖两套主题、禁用、悬停、按下、选中和键盘焦点，DPI 改变时保持清晰。按实际可见笔画的光学尺寸验收，不能只检查 iconSize：独立加号应充满图标主体，避免复用复合图标的小角标。保存、取消、确认等表单动作仍使用清楚的文字；下拉框保留其选择语义。活动栏选中项具有固定的可见标记。

上述 frame 和图标规则同步补入通用 Qt 开发规范；项目主题规范记录具体配色和实现尺寸。

## 验收依据

重点检查左组移空、右组移空、连续横向三列／四列同排、移空中间列后自动收起、全部合并、最后页浮出与收回、未保存关闭取消、组内排序、中心与四边放置、Esc 与无效落点。上下布局仅验证用户明确操作的结果。移动前后核对控件身份、编辑内容及撤销记录；验证进程页不重复、终端不重建。

提供隔离演示内容的两主题截图，检查边框、图标、工具提示、分屏预览和窄窗布局；真实桌面拖动、实际系统 DPI 与离屏渲染的覆盖范围分别说明。保留密码功能和原有核心／协议回归测试。开发继续由 GPT-6.1-sol、xhigh 执行，主代理制定方案并审查验收。
