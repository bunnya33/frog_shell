# RabbitShell systemd 服务面板设计

日期：2026-11-05。状态：已按确认方案接入 0.1.13 Qt 程序；实现边界与实际验证分别见《RabbitShell-systemd服务实现记录.md》《RabbitShell-0.1.13验证记录.md》。本设计本身不作为通过凭据。

本次补充：新增服务可浏览服务器选择程序；服务列表增加自定义服务删除。此前未纳入首版的新增／删除规则以下文为准。

## 1. 位置与面板行为

用户确定服务管理与终端、端口转发放在同一底部面板，增加第三个“服务”页签，不增加左侧服务入口。

```text
终端   端口   服务                              [当前页操作] [最大化] [隐藏]
──────────────────────────────────────────────────────────────────────────
服务名称               运行状态       开机自启          描述
nginx.service          ● 运行中        已启用            Web 服务
docker.service         ● 已停止        已禁用            容器服务
```

- 保持页签与工具按钮同一行，不添加重复的“服务管理”标题行。
- 最大化、还原、隐藏属于整个底部面板，三页共用现有行为与图标；最大化仅增加同一四角图标的选中背景，不替换图标。
- 切换页签保持面板尺寸，各页保留自己的选中项、滚动位置和输入。回到服务页时刷新实际状态，刷新按完整 unit 名称保留选中项，不按行号恢复。
- 终端专属的新建、拆分、垃圾桶等按钮仅在终端页出现；服务页显示自己的新增服务与刷新操作，按钮采用纯图标、tooltip 和无障碍名称。
- 打开、隐藏或关闭底部面板均不启停服务，也不结束已有终端和端口转发。关闭服务器工作区、断开连接或退出 RabbitShell 仅结束本地查询和控制连接，不主动停止服务器服务。

## 2. 服务列表与详情

首版管理系统级 `.service` 单元。列表同时考虑已经加载的 unit 与已安装的 service unit 文件，不能遗漏未加载的已停止服务；实例化服务保留完整实例名称。其他 unit 类型及当前用户的 `systemctl --user` 作为后续扩展，不与首版混在同一列表。

| 项目 | 规则 |
| --- | --- |
| 服务名称 | 显示完整 unit 名称，可复制；以名称作为行身份，不依赖 PID 或当前排序 |
| 运行状态 | 显示运行中、已停止、启动中、停止中、失败等，文字配合颜色；`active (exited)` 明确为已完成／退出，不能暗示有进程正在运行；未知状态保留真实值 |
| 开机自启 | 独立显示 enabled、disabled、static、masked、indirect 等实际状态的可读文本，不把所有状态简化成二态开关；运行状态变化不自动修改自启 |
| 描述 | 使用服务自身描述；长内容省略并通过 tooltip 查看 |
| 搜索与筛选 | 服务页内提供紧凑名称／描述搜索，以及全部、运行中、已停止、失败筛选；不改动端口页已有的无搜索设计 |
| 详情 | 从行菜单或双击打开按需详情，显示完整名称、状态、自启、主 PID、启动时间；内存、CPU 等可选字段有可靠数据时才显示 |

列表沿用 Dracula／GitHub Light、圆角卡片、交替行色、可辨边界及可拖列宽。列宽按本地偏好保存，刷新不清空选中、排序与滚动。窄面板优先保证名称与状态可读，完整详情按需查看。

初始未进入服务页时不查询；首次打开才检测和读取。服务页可见且所属服务器工作区活动时低频刷新，建议起点为 5 秒；隐藏、切页或切换服务器后停止周期查询。每次只允许一组列表刷新在途，操作完成后触发一次合并刷新，不为每行创建定时器或长期控件树。

## 3. 操作

选中行可显示一组复用的操作图标，右键提供同样菜单；动作始终绑定发起时的完整 unit 名称。搜索、排序、自动刷新或焦点变化不能把动作重定向到另一服务。

| 操作 | 交互 |
| --- | --- |
| 启动 | 对停止的服务发起 start，显示启动中，重新查询状态后展示结果 |
| 停止 | 对活动服务发起 stop；确认中明确服务器和服务名称 |
| 重启 | 使用明确的重启操作，确认中说明会短暂中断服务 |
| 重新加载配置 | 仅服务声明支持 reload 时提供；不将 reload 失败偷偷升级为 restart |
| 启用／禁用开机自启 | 与当前运行状态分开设置，不附加 `--now`；static、masked 等不能直接切换时显示原因，不自动解除屏蔽 |
| 查看日志 | 按需使用已有 `journalctl`，读取所选服务最近有限条数日志；手动刷新，不默认开启无限跟随 |
| 查看详情／复制名称 | 普通只读操作；可选字段不可得时省略 |
| 新增服务 | 工具栏加号打开配置表单，可浏览远端选择程序；保存、开机自启与立即启动明确区分，规则见第 3.1 节 |
| 删除服务 | 右键提供“删除服务…”；仅删除来源明确且可管理的独立自定义服务，确认后停止、取消自启、移除配置并刷新，规则见第 3.2 节 |

首版单项控制，包含新增和删除独立自定义服务；不增加批量停止／重启、任意服务文件编辑、自动安装依赖或自动解除 mask。操作在途时禁止同一服务重复发起控制，并保留其他服务的查看能力。控制命令返回成功后还需重新读取实际状态，不能仅因按钮已点击或 SSH 请求已发送而显示成功。

等待过久或 SSH 断线时显示“结果未知，请刷新确认”，不据此推断远端操作已回滚或已停止。恢复连接不自动重放启停命令。停止本地读取不承诺撤销已提交给 systemd 的任务。

### 3.1 新增服务与选择远端程序

服务页工具栏提供加号按钮，tooltip 为“新增服务”。创建系统级服务的表单包含：

| 字段 | 交互 |
| --- | --- |
| 服务名称 | 输入基础名称，界面明确最终 `.service` 名称；校验允许的名称，不接受路径或任意 unit 类型，已存在的服务不覆盖 |
| 描述 | 可选的服务说明，作为数据保存，不执行其中内容 |
| 可执行程序 | 路径输入框旁提供文件夹图标；既可手动输入绝对路径，也可浏览当前 SSH 服务器选择文件，不能误用本地文件选择器 |
| 启动参数 | 独立输入并按参数规则解析、引用；不作为 shell 脚本执行，不自动添加 `&`、管道或重定向 |
| 工作目录 | 可输入或浏览远端目录，首次选程序时建议程序所在目录；用户改过后不再自动覆盖 |
| 运行用户 | 明确指定服务器已有账号，展示所选账号；不创建系统账号、不静默改成 root |
| 异常退出后重启 | 独立设置，生成合适的重启策略；默认故障后重启并留出重试间隔 |
| 开机自启 | 显式选择是否启用，保存时不隐含立即启动 |
| 保存后立即启动 | 与自启分别选择，默认关闭；用户可只创建配置，也可明确选择保存并启动 |

远端文件选择器复用资源管理的紧凑路径面包屑／点击空白编辑路径、返回／前进／上一级／主目录／刷新。起点为当前工作区目录，独立维护选择器导航，不改变主资源树目录、选择、展开状态。单击整行选择、双击目录进入，选中文件后确认返回绝对路径；可取消且不丢失表单其他输入。程序与解释器为单文件选择，工作目录为目录选择，不使用多选或复选框。

文件选择只返回路径，不下载、不上传、不执行，也不自动修改权限。所选二进制或有有效 shebang 的脚本需能由运行账号执行；普通 Python／Shell 等脚本提供独立“解释器”字段，也支持从远端选择已有解释器，再以脚本作为参数生成 ExecStart。不能仅凭扩展名假定服务器已安装解释器。可检查的信息在保存前提示，无法确认时不声称一定可启动；实际启动结果以 systemd 返回及复查为准。

保存前显示将创建的服务名称、运行用户、程序、工作目录、自启和立即启动选择；提供只读生成配置预览。写入 `/etc/systemd/system/<名称>.service` 必须具备相应权限，拒绝覆盖现有同名文件、别名或屏蔽项。成功写入后执行 daemon-reload，按选择单独 enable 和 start；各步保留明确结果。写入配置属于用户请求的服务器修改，不上传远端辅助程序或新增工具。后续步骤失败时显示配置是否已创建、自启是否已设置、启动是否完成，不自动反复提交或假报全部成功。

### 3.2 删除服务

systemctl 没有通用的“删除服务”命令；客户端需要核对单元来源，再执行停止、取消自启、删除配置、daemon-reload 的工作流。右键菜单使用“删除服务…”，垃圾桶 tooltip 使用同名文字，不与停止服务混淆。

- 可删除当前工具创建的服务，以及来源明确、位于 `/etc/systemd/system/` 下的独立自定义普通 `.service` 文件；不要求只能删除 RabbitShell 创建的服务。当前账号必须具有控制和删除该文件的权限。
- 来自 `/usr/lib/systemd/system/`、`/lib/systemd/system/` 等发行版／软件安装目录的服务，提供停止和禁用开机自启；删除入口禁用并说明应通过对应软件的卸载流程处理。不能把删除供应商文件当作卸载，也不能在只删除本地 override 后误称整个服务已删除。
- transient／生成单元、模板及共享模板实例、别名、符号链接、带独立 drop-in 或其他来源不明确的复杂配置，首版不自动清理。详情列出来源和限制，不跟随链接删除任意目标、不删除共享模板或整个 `.d` 目录。普通列表不必因此增加固定来源列。
- 确认框显示当前服务器、完整服务名称、配置路径、运行状态、自启状态，以及“将移除服务配置，保留可执行程序和业务数据”。运行中的服务按钮为“停止并删除”，其余为“删除服务”；一次确认包含预定步骤，不再为每一步连续弹窗。
- 确认后重新核对完整 unit 身份、来源和配置是否变化；变化或权限不足时停止操作。活动服务先停止并复查，取消其自启关联后仅删除已确认的配置文件，再 daemon-reload 和刷新。前一步失败时不盲目继续删除，不递归删除程序、工作目录、日志或数据。
- 对 timer／socket 等激活来源或依赖影响能够确认时在确认框说明，不自动删除其他 unit。无法可靠处理的关联由用户先处理，不许诺删除一个 unit 就清除了所有启动来源。
- 超时、掉线或部分成功时列出已完成步骤和待确认状态；不自动重放，也不以恢复启动服务作为未经请求的回滚。重新加载后按实际结果显示，仍被依赖引用的 `not-found` 状态不能当成删除失败后无限重试。

删除完成只更新服务列表并保留其他行状态，保留终端、端口转发、编辑器和主资源树状态。

## 4. 服务器能力与权限

遵循远端零安装：只使用服务器现有 SSH exec、systemd／systemctl；日志额外依赖已有 journalctl。不上传 Agent、二进制、脚本文件或安装运行时。

- 首次进入时检测命令和 system manager 的实际可达性；仅找到 `systemctl` 不代表能用。不是 systemd 系统、容器无总线、SSH 禁止 exec 等情况在页内说明原因，保留其他两个页签正常工作。
- 能读取的服务正常显示；日志不可读仅影响日志，不使服务列表整体失败。缺少可选信息不提示安装工具。
- 控制使用当前 SSH 身份已有权限。首版不新增隐式 sudo、sudo 密码保存或 SSH 密码复用；权限不足明确显示服务器返回原因，并保留状态查询。需要特权的账号应由服务器已有权限策略授权，不自动修改 sudoers 或 polkit。
- 只执行允许的固定动作，unit 名称作为经过校验、正确引用的参数处理；禁止直接把描述、日志或文本输入拼进可执行 shell 命令。
- 设置无颜色、无分页和不触发远端交互授权；无权限时返回明确错误，不能让远端密码或 pager 提示无限占用任务。

## 5. 实现约束与验收重点

开发继续采用 C++20／Qt Widgets 和现有 SSH 认证、主机指纹流程。服务任务使用异步、有超时、有界输出的执行路径；现有监控 `Session::execute()` 为短时同步采样，不直接复用它执行长时间 start／stop／restart，也不把服务控制命令写入用户的交互终端。

服务传输按使用需要建立和回收，与 SFTP 及隧道的生命周期分别处理；不得从多个线程同时操作同一 libssh2 session。日志、错误文本和列表设置容量上限，隐藏时不持续拉取；不为每个服务建立一条 SSH 连接。

开发时至少验证：三页切换与最大化保留、unit 身份及刷新保选、已停止／未加载服务可见、复杂自启状态、部分能力缺失、权限拒绝、不支持 systemd、操作失败／超时／断线后的未知状态、不自动重放控制、日志有界，以及工作区销毁后资源回收。自动化使用临时配置、offscreen 和本机隔离 SSH fixture，不操作真实服务器上的服务。实际 systemd 兼容性需另有对应系统验证，模拟返回不能当作真实系统验收。

新增／删除另需验证：远端选择器与本地路径区分、选择文件及取消、导航不改主资源树、解释器和参数引用、中文／空格路径、运行账号与权限检查、同名拒绝、自启与立即启动独立、创建部分失败；删除确认取消、运行中停止失败、来源变化、供应商服务及模板／链接／drop-in 拒绝、步骤中断，以及程序和业务数据始终保留。

0.1.13 使用独立目录包和 portable 文件名；0.1.12 产物保持不变。实际通过/跳过、兼容性与保守删除边界见实现和验证记录。
