# RabbitShell SSH 隧道实现方案

日期：2026-11-04。界面方案基于 RabbitShell 0.1.9，最大化按钮修正已于 0.1.10 交付。0.1.11 已接入第一阶段的真实本地 TCP 转发；完成范围和实际验证见 [0.1.11 验证记录](RabbitShell-0.1.11验证记录.md)。本方案保留后续阶段的设计，不将其当作已交付能力。

## 1. 结论与推荐范围

可以实现。当前使用的 libssh2 已有标准 SSH TCP 转发接口，不需要在服务器安装 VS Code Server 或 RabbitShell 常驻程序。实际可用性取决于 SSH 服务端是否允许相应转发，以及目标服务是否可达。

端口转发是 SSH 隧道的常见用途。用户截图中的公网 HTTPS 地址、专用／公开可见性属于带云端中继的端口分享体验，不能直接等同于 SSH 本地转发。本方案采用其面板和编辑交互，连接目标仍为当前 SSH 服务器；默认提供本机回环地址，不生成公网网址，不引入云端账户或中继。

**用户确认的首要原则（2026-11-04）：远端零安装。** RabbitShell 使用服务器已有的 SSH 服务及其开放的能力，不要求安装任何额外工具、运行时、Agent 或远端 Server，也不上传辅助程序来补齐信息采集。隧道核心仅依赖 SSH TCP 转发能力，不依赖 `ss`、`lsof`、Python、Node.js、SFTP 或远端 exec 权限。可选信息能从当前环境直接取得才展示，取不到就省略；不为此提示安装、请求提权或阻止连接与转发。这项原则优先于对齐 VSCode 的信息展示完整度。

建议分三个阶段：本地转发 → 远程转发 → SOCKS5 动态转发。先把日常访问远端 Web、数据库的链路、状态和释放做完整，再增加方向与协议。

| 类型 | 解决什么问题 | 监听在哪里 | 目标地址由谁解析、连接 | 阶段 |
| --- | --- | --- | --- | --- |
| 本地转发，相当于 `ssh -L` | 本机访问 SSH 服务器或其可达内网中的服务 | RabbitShell 所在电脑 | SSH 服务器 | 第一阶段 |
| 远程转发，相当于 `ssh -R` | SSH 服务器一侧访问本机或本机可达网络中的服务 | SSH 服务器 | RabbitShell 所在电脑 | 第二阶段 |
| 动态转发，相当于 `ssh -D` | 支持 SOCKS5 的程序按需访问多个远端目标 | RabbitShell 所在电脑 | SOCKS5 请求指定目标；域名交给 SSH 服务器解析 | 第三阶段 |

本地转发示例：本机浏览器访问 `http://127.0.0.1:18080`，经 SSH 连接后到服务器的 `127.0.0.1:8080`。这里目标 `127.0.0.1` 指 SSH 服务器自身；也可填写服务器可达的另一台机器，例如 `10.0.0.12:5432`。

远程转发示例：服务器监听 `127.0.0.1:19090`，收到连接后经 SSH 转给本机的 `127.0.0.1:3000`。这里目标 `127.0.0.1` 指运行 RabbitShell 的电脑。界面用“本机监听／服务器监听”“服务器访问的目标／本机访问的目标”明确区分，不只写容易混淆的“源地址、目标地址”。

首版仅做 TCP。UDP、VPN、HTTP 反向代理、多跳 SSH、自动发现远端进程端口不随本功能自动获得；跳板机连接属于另一项连接管理能力。

## 2. 底部端口面板（本轮确定）

### 位置与公共工具栏

底部同一面板提供“终端 / 端口”页签；左侧活动栏保持服务器状态和资源管理，不增加隧道入口。页签与右侧动作在同一行，不额外叠加标题栏。初始仍进入终端，切换页签复用现有内容和状态。

- 终端页显示现有新建、当前终端、拆分、关闭等操作；端口页只在空态或列表末尾提供“添加端口”，不在工具栏重复放添加按钮。终端专属按钮不出现在端口页。
- 最大化、还原、隐藏属于整个底部面板，两页共用。最大化和还原始终使用同一个四角图标；最大化时仅增加选中背景／边框，tooltip 和无障碍名称改为“还原面板”，还原后取消选中。
- 最大化只占满右侧工作区，保留左侧栏目与 footer；切换终端／端口页签保持当前大小。还原恢复原分隔高度；隐藏时恢复上方编辑区，再通过已有显示面板入口打开上次页签。
- 页签切换、隐藏和最大化不停止任何终端或转发，也不重新创建会话。运行数量如需提示，仅放在端口页签旁；不再增加另一套固定 footer 隧道统计。

### 三列主表

首版仅提供本地转发，默认是本机 `127.0.0.1:本地端口` → 当前 SSH 服务器 `127.0.0.1:远端端口`。

| 列 | 显示与操作 |
| --- | --- |
| 本地端口 | 本机监听端口，例如 18080；支持行内编辑与复制完整本地地址 |
| 远端端口 | 当前服务器上的目标端口，例如 8080；支持行内编辑 |
| 启用 | toggle 控制本条转发的启动／停止；短状态和行操作菜单容纳于本列，不另加状态、操作列 |

移除来源、可见性、运行进程、名称、类型和转发网址等固定列，不添加搜索或筛选。进程若能直接取得，可放在按需详情中；没有信息时不显示任何占位，不主动为此部署工具或启动周期查询。流量信息也只按需进入详情。

非默认地址在对应端口下方显示紧凑次行，或在窄布局中折行；完整地址可通过 tooltip 查看。不能只写两个端口而隐瞒已配置的另一台内网目标。表格沿用两套主题、清晰外边界和选中状态；不照搬截图的长竖网格。行菜单提供编辑、复制本地地址、高级设置、删除；在选中／键盘焦点行可发现。

### 新增与行内编辑

1. 空列表显示“暂无端口转发”和“添加端口”；有数据时在列表末尾保留添加行。点击添加直接生成草稿行，不弹普通新建对话框。
2. 输入远端端口时，本地端口默认跟随为同号；用户手动修改本地端口后不再覆盖它。两项均须为 1–65535 的十进制整数，拒绝 0、小数、负数、字母和溢出值。
3. Enter 校验并保存为关闭状态；Esc 取消本次编辑。新建行两项全空且点击行外时取消；有效输入点击行外保存但不自动启用；非法或缺少必要输入时保留草稿，在字段旁显示具体原因。
4. Tab 或鼠标在同一行内切换字段、开关和行菜单不算离开整行，不提前提交。切到终端时仍允许操作终端，未完成草稿回到端口页后继续，不抢回焦点。
5. 点击有效草稿的开关可作为显式“保存并启动”；提交配置本身与启动连接分别处理。重复点击添加不产生无限空草稿，先处理已有草稿。
6. 已停止的规则可以行内修改，取消恢复旧值。运行中的规则修改端口或地址时，先保留当前配置与流量；使用明确的“应用并重启 / 取消”行内操作，确认后仅重启该规则并结束其旧 TCP 流，失焦不自动重启。

### toggle 与失败状态

- 关闭表示该规则已停止，打开表示 SSH 与监听已成功建立。启动中、停止中、等待认证显示简短文字并禁用重复切换，不能点击后立即伪装为已运行。
- 启动失败回到关闭状态，并在该行显示原因，例如“本地端口 18080 已被占用”；允许修改后再试。不会自动改成本地其他端口。
- 关闭开关停止该规则的新连接并结束其现有流；保留配置，其他转发与终端继续运行。开关控制本次运行，不默认为下次连接自动启动。
- 删除已停止规则可直接执行；删除运行规则使用一次明确确认，取消保持原状态。配置删除不影响服务器上的服务或文件。

### 高级设置与离线维护

只把不常改的必要项放进该行的高级设置：本地监听地址、远端目标地址、可选备注、随工作区连接启动。两端地址默认 `127.0.0.1`；本机可选 `::1`，非回环绑定作为高级项明确范围。首版类型固定为本地转发，不显示未实现的远程转发或 SOCKS5 选项。

“随工作区连接启动”默认关闭，与当前启停开关分开。自动重连也默认关闭，实际实现前不显示选项。地址和端口分字段保存，IPv6 完整端点以 `[IPv6]:port` 展示。本机地址须为有效本地 IP 或明确通配地址，目标允许域名。

连接管理的服务器右键可通过“端口配置”离线维护同一份规则、复用同一紧凑列表。保存不连接；离线启动明确标为“连接并启动”，打开所属工作区的端口页后执行。没有工作区的隐藏常驻模式不在首版范围。

不自动把任意端口认作网页，不生成云端地址；复制只复制本地端点。打开浏览器仅在用户明确选择 HTTP／HTTPS 时提供。

## 3. 生命周期

隧道归属于服务器工作区，不归属于某个终端。后台运行状态与面板显示状态分离。

| 操作／事件 | 行为 |
| --- | --- |
| 关闭某个终端、关闭全部终端 | 隧道继续运行 |
| 切换服务器页签、隐藏隧道列表、最小化窗口 | 隧道继续运行，不重建连接 |
| 停止一条隧道 | 停止接受新连接并结束该规则现有转发流；其他规则与终端不受影响 |
| 主动断开本服务器 | 停止该服务器终端、传输和隧道；保存隧道配置 |
| 关闭服务器工作区或退出应用 | 沿用现有汇总关闭流程，把运行隧道数量加入影响说明；停止规则、回收连接后完成关闭 |
| 交互 SSH 会话意外断开 | 不据此断定独立隧道连接也已断开；仍健康的隧道保留，分别显示终端与隧道状态 |
| 隧道 SSH 连接意外断开 | 该连接承载的转发流结束，状态改为断开；保留规则。没有自动重连选项时等待用户启动 |
| 手动停止后网络恢复 | 不自动再次启动；用户主动停止优先于重连计划 |

隧道连接断开后，原来的 TCP 会话不能恢复。自动重连只能重新建立 SSH 连接和监听，浏览器、数据库客户端等需要自己重新连接。

如果启用自动重连：每个服务器只安排一条重连任务，采用有上限的退避与抖动，例如 1、2、5、10、30 秒，最多 10 次后显示失败。认证失败、指纹变化、明确的端口冲突或权限拒绝停止自动尝试；需要密码时统一进入等待输入状态，不反复弹窗。

掉线时关闭本机监听和现有流，恢复后按原端口重新绑定；端口已被其他程序占用时明确失败。远端监听的释放还受 SSH 服务端对断线的检测影响，不能承诺网络中断瞬间完成释放。

启用开关在运行时的 tooltip 明确“停止转发并结束其连接”，不为每次关闭开关叠加确认。删除运行中的规则复用一个确认流程，说明会先停止再删除；普通删除不会影响服务器上的文件或服务。

## 4. 状态与错误

每条规则至少包含：已停止、连接中、等待输入、启动中、运行中、重连等待、停止中、失败。运行中表示转发监听已经建立，并不表示目标业务始终健康。

- 本地转发的 `QTcpServer::listen()` 成功且专用 SSH 连接就绪，才显示运行中。
- 远程转发须收到服务端接受监听的响应；动态转发还须本地 SOCKS5 监听就绪。
- 某个客户端连接目标失败，仅结束该条 TCP 流，保留隧道监听；行内保留可查看的最近错误，不能因此把所有隧道判为失败。
- 区分本机端口占用、绑定地址不可用、SSH 认证问题、转发被服务端拒绝、目标无法连接及网络断开。
- 错误必须基于实际返回信息；部分 SSH 转发拒绝只有通用错误，不能凭空判断是 DNS 还是具体哪条管理员规则。
- 不以固定轮询探测目标服务来维持绿色状态。需要测试时由用户显式触发，并标注“最近一次测试结果”。

本地监听默认只允许本机访问。非回环绑定时在表单就地显示可访问范围，不自行修改防火墙。远程转发的 `GatewayPorts`、`AllowTcpForwarding`、`PermitOpen`、`PermitListen` 等服务端策略可能限制或改变行为；服务器可能重写请求的绑定范围。界面显示“请求监听地址”，不在无法验证时宣称远端端口一定只对回环开放，也不自动修改 sshd 配置。

### 可选端口与进程信息

- 手动填写目标与端口始终可用；自动发现监听端口、关联运行进程是可选增强，不作为建立隧道的前置条件，也不因发现端口而默认转发。
- 仅使用服务器已有且当前账号可读取的系统接口或工具。例如 Linux 上可使用已有的 `ss`／`lsof` 或可读的 `/proc`；不假定它们一定存在或可访问。没有可用路径时结束探测，不自动安装、不下载执行辅助二进制、不要求 Python／Node.js、不运行 sudo、不修改远端环境。
- 仅在能确认目标属于当前 SSH 服务器及可见网络命名空间时关联监听进程。匹配包含监听地址与端口，不能只按端口号猜测；目标在另一台内网机器时省略。远程转发的服务端监听通常属于 sshd，不将它标成业务目标进程。
- 探测与转发独立，复用现有可用的只读采集通道；没有该通道也不阻止隧道。设置超时和输出上限，不占用用户交互终端，不进入专用隧道的数据转发循环。仅在用户打开相关详情时按需查询，详情可见期间可低频刷新，收起后停止该附加采样；只打开端口列表不触发进程采样，本次会话已确认不支持的能力不反复探测。
- 信息失效或查询失败后撤下对应附加内容，不将缓存继续当作当前事实。缺工具、权限不足或查询超时不弹窗、不显示安装提示，不改变隧道运行状态。真实的认证失败、端口占用、SSH 禁止转发等核心操作错误仍明确显示。

## 5. 与现有架构的衔接

当前 `Session::run()` 在同一个 worker 中执行目录、文件和监控任务；部分任务采用阻塞调用，监控 `execute()` 最长可占用约 8 秒。直接把转发塞进该循环，会让网页或数据库流量被不相关任务拖慢。因此推荐独立承载：

```text
服务器工作区 / 连接身份（profile.id）
  ├─ 现有交互 Session：终端、资源管理、监控
  ├─ 现有传输 Session：上传、下载
  └─ TunnelService：按需创建的一条专用 SSH 连接
       ├─ 规则 A 的监听与多个 TCP 通道
       ├─ 规则 B 的监听与多个 TCP 通道
       └─ 规则 C 的监听与多个 TCP 通道
```

- 同一服务器的多条规则共享一条专用隧道 SSH 连接，不为每条规则或每个 TCP 客户端各开 SSH 连接／线程。不同服务器按需隔离。
- 服务没有运行规则时不创建；最后一条规则停止且通道清理完成后销毁其 SSH 连接和 worker，不后台空转。按规则已启动但暂时没有客户端连接时，保留必要监听与 SSH 保活。
- 使用 QObject worker 加 Qt 事件循环；QTcpServer、SSH 传输适配器、本地原生 socket 与 libssh2 句柄在同一所属线程使用。界面只收发命令和状态，不处理转发 payload。本地 TCP 流使用原生 socket 加 QSocketNotifier，以正确保留双向半关闭。
- libssh2 隧道连接使用非阻塞状态机；根据 `libssh2_session_block_directions()` 和 socket 就绪事件推进，避免不断定时遍历空通道。
- SSH TCP socket 的加密字节只由一个传输适配器读取。0.1.11 使用完整的 libssh2 SEND／RECV 回调，经有界 QTcpSocket 缓存传递加密字节；libssh2 不再直接读写该 descriptor，避免两者争抢数据。
- 同一 libssh2 session 的开通道、监听、取消监听等请求须按其可重入规则串行推进；EAGAIN 时保留操作及参数，不能从其他线程调用同一 session。
- 不为隧道打开 PTY、执行监控命令或初始化 SFTP。

### 可复用部分

复用 `Profile` 的 SSH 身份、`ConnectionRepository`／`SecretService` 的安全凭据流程和 known_hosts 主机指纹规则，界面与连接管理共享认证提示队列。已输入且尚在会话中可用的临时凭据可用于专用连接，最后使用者结束后释放；不把“不保存密码”偷偷变为持久保存，也不假定另一个 SSH 会话可以直接借用认证结果。

必要时先抽取小范围的认证／主机校验组件。不要复制整份 Session 的 PTY、SFTP 与监控逻辑，也不在这次功能中重写整个应用连接架构。

## 6. 数据转发与资源边界

| 功能 | 现有依赖可用的能力 |
| --- | --- |
| 本地 TCP 转发 | QTcpServer 接受本机连接；公开 `libssh2_channel_open_ex("direct-tcpip", …)` 请求服务器连接目标，并显式指定小接收窗口 |
| 远程 TCP 转发 | `libssh2_channel_forward_listen_ex()`、`forward_accept()`、`forward_cancel()`；本机连接配置目标 |
| 动态 SOCKS5 | 应用解析有界 SOCKS5 握手，成功后使用 direct-tcpip 转发；libssh2 不直接提供 SOCKS5 服务端 |
| 双向数据与关闭 | `channel_read_ex/write_ex`、`channel_send_eof/eof` 和非阻塞通道清理 |

每个接受的 TCP 客户端对应独立 SSH channel，双向流量不能混用。实现必须处理部分读写、EAGAIN、连接超时、半关闭、发送尾部数据后再 EOF，以及停止过程中到达的新连接。

采用背压：目标暂时写不出去时暂停源端读取，不把所有字节堆入 QByteArray。先以每方向 64 KiB 应用暂存高水位、每服务器 32 条流、应用 64 条流为验证起点；超限拒绝新流并显示原因，不丢弃既有流中的数据。Qt socket 写队列／读缓存也必须纳入上限，禁止只限制自建容器却无限调用 write()。

这些数值不能直接换算为进程仅占“连接数 × 128 KiB”：libssh2 内部队列、socket 和加密库还有额外内存。0.1.11 的 direct-tcpip 采用公开 channel-open 接口，将每通道初始接收窗口设为 64 KiB、最大数据包设为 16 KiB，SSH 传输适配器读写缓存分别不超过 128 KiB，并给每条 SSH 会话的 libssh2 分配器设置 16 MiB 预算。每服务器最多 32 条活动流，应用合计最多 64 条；超限拒绝新流。远程 accept 的窗口路径留到后续阶段验证，不维护库私有补丁。最终内存趋势以 Release 测量为准。

有流量时 UI 可每 500ms–1s 合并一次统计；面板隐藏后降低／停止可见数字刷新，但不停止数据流。计数器使用整数、样本保持固定容量；日志记录状态和错误，不保存转发 payload 或逐包日志。

动态转发初期仅支持 SOCKS5 CONNECT，支持 IPv4／IPv6／域名和分包握手，限制握手长度、时间及待认证连接数量。域名交给服务器解析；客户端已经提交 IP 时，不把它声称为远端 DNS。初期只绑定本机回环，不开放无认证的局域网 SOCKS 服务，不自动改系统代理；BIND、UDP ASSOCIATE 后置。

## 7. 配置模型

以独立、带版本的 `tunnels.json` 保存可移植规则，关联稳定的 `profileId`；使用 QSaveFile 原子写入及进程间锁。运行状态、速率、错误与当前连接不写入规则文件。0.1.11 的实际字段为 `id / profileId / localAddress / localPort / remoteAddress / remotePort / name / autoStart`；类型固定为本地 TCP 转发，没有自动重连字段。每服务器最多保存 64 条规则，配置总计最多 1024 条且不超过 1 MiB；格式错误时拒绝覆盖。

以下统一模型是后续扩展方向，不代表首版已提供所有字段和类型：

```text
TunnelRule
  id                  规则 UUID
  profileId           所属服务器连接 UUID
  name                可选备注，不作为主表列
  kind                local / remote / dynamic
  bindAddress         请求监听地址
  listenPort          监听端口
  destinationHost     目标域名/IP，dynamic 无此字段
  destinationPort     目标端口，dynamic 无此字段
  autoStart           随工作区正常连接启动，默认 false
  reconnectPolicy     手动 / 有限退避重连，默认手动
```

启动时校验同机规则监听冲突，尤其不同服务器占用同一本地端口；实际 bind 结果是最终依据。通配绑定、IPv4／IPv6 双栈冲突纳入测试，不能仅比较字符串。

运行中修改监听或目标：草稿不改变运行配置，明确选择“应用并重启”后才提交并重启；仅影响该条规则，不能静默让现有连接改指向另一个目标。改备注可直接更新。修改所属服务器的地址／账号／认证使用连接配置修订号，旧异步结果不能启动到新的服务器身份；既有连接显示待重新连接，避免静默混用。

复制服务器或规则生成新 UUID，默认不复制自动启动／自动重连意图；不复制凭据。导出可选携带隧道配置且不含秘密，导入后不自动启动。后续支持 SSH config 的 LocalForward／RemoteForward／DynamicForward 时先展示转换结果，不执行 ProxyCommand 或 Match exec。

## 8. 分阶段交付与验收

### 第一阶段：本地转发

实现统一规则模型、底部终端／端口页签与离线配置、三列列表及行内编辑、本地固定端口转发、独立 SSH 承载、toggle 启停、随连接启动、状态／错误／按需流量、完整关闭及有界缓存。自动重连可以在同阶段后半段补齐，未实现前不展示该选项。

验收至少包括：HTTP 与长 TCP 流、双向随机字节一致、并发流、半关闭、目标拒绝／域名失败、端口占用、服务器拒绝转发、网络断开、停止后释放端口、关闭最后终端不影响隧道、工作区退出正确清理、凭据取消与指纹变化。

### 第二阶段：远程转发

复用规则与连接引擎，增加远端监听／取消、服务端策略失败、同一连接的多个远端端口、目标在本机侧的地址语义。验证“远程监听成功但本机目标未启动”的逐流失败行为，以及断线后的端口释放边界。

### 第三阶段：SOCKS5

增加有界握手状态机、域名／IPv4／IPv6 请求、分段与无效握手、CONNECT 结果映射和连接限额。保持应用级代理设置，不自动设置系统代理或承诺 VPN 能力。

### 共同验证

- 在缺少 `ss`／`lsof`／Python／Node.js、进程信息权限不足或不允许远端 exec 的隔离环境中，SSH 服务端允许转发时手动隧道仍可使用；附加信息自动省略，无安装／提权提示，不执行远端辅助程序部署。
- 现有 Paramiko fixture 需要增加 direct-tcpip／remote-forward 支持，不能用当前 PTY echo 结果替代转发验证。
- 在隔离 OpenSSH 环境验证允许／禁止转发及 GatewayPorts 等真实策略；不使用用户生产服务器做实验。
- Windows、macOS、Linux 分别验证 socket notifier、端口绑定与退出释放，再声明对应客户端可交付。
- 测量零规则、仅监听、1／8／32 条活动流、慢接收背压及反复启停后的 Private Bytes／工作集、线程数、句柄和空闲 CPU。验收目标是缓存有界、无持续增长、空闲无忙轮询，最终阈值由基线测量确定。
- 同时进行终端输入与大文件传输，确认它们不会阻塞专用隧道的调度；也不把共享网络带宽限制误判为代码阻塞。
- 两主题核验规则列表、长端点、等待认证、失败、停用及窄窗，无需为此新增复杂图表。
- 覆盖全空／半填／非法／有效草稿的 Enter、Esc、跨行失焦、行内 Tab、切页签和再进入；运行规则编辑失焦不重启，启停处理中不重复提交，失败后开关回关，重复本地端口不自动换号。
- 面板最大化前后使用同一图标，以选中背景区分；在最大化状态切换页签、隐藏再打开，终端与转发继续，编辑布局和原高度正确恢复。

0.1.10 交付的可操作原型数据全部模拟，没有建立真实隧道。用户确认后，0.1.11 接入第一阶段的真实本地转发；不以原型验证代替 SSH 数据转发验证。远程转发、SOCKS5、云端分享和自动重连仍按后续阶段处理。

运行状态只表示本机监听和隧道 SSH 连接就绪。SSH 服务端通常在客户端第一次访问、实际打开 direct-tcpip 通道时才检查转发目标策略；此时目标不可达或策略拒绝属于该条 TCP 流失败，不能伪装为启动前已验证了业务服务。错误要出现在对应规则中，不需要为确认服务健康而常驻探测。

生产端口面板使用已有 SSH 服务，不依赖工作区的 SFTP 成功：只有 SSH 已认证、但普通文件会话因 SFTP 不可用而失败时，手动端口转发仍可独立启动。没有普通在线会话时，自动启动不反复尝试；用户可以显式启动并按需完成认证。

## 11. 旧版主机信任记录的换行兼容

0.1.12 已修正该问题。隔离 ECDSA 与 RSA 校验套件各为 36 passed／0 failed／0 skipped，版本回归与部署结果见 [0.1.12 验证记录](RabbitShell-0.1.12验证记录.md)。

0.1.11 抽取共享主机校验后，QFile 按二进制读取旧版 Windows `known_hosts`。旧文件由文本模式写入，使用 CRLF；libssh2 的单行解析器只去掉 LF，密钥字段没有尾随注释时，CR 会进入保存的 Base64 文本。库随后按文本比较当前密钥，于是相同公钥也可能被误判为变化。这是文件读取兼容性回归，与密码和服务器是否安装远端程序无关。

修正只规范化记录的行终止符，保持 LF、CRLF、混合换行和没有末尾换行的已有记录可读；不通过随意 trim 密钥字段、忽略格式错误或自动重新信任绕过校验。原有文件大小／行长上限、锁、未知主机确认、变化拒绝及原子保存规则继续适用。升级兼容既有记录，不删除或重写用户现有的信任文件。

同时区分主机密钥不匹配与校验过程失败：只有确认密钥不匹配才显示“主机身份变化”；文件无法读取、格式错误或其他校验错误报告具体原因并中止连接，不用变化弹窗代替这些错误。普通会话和专用隧道使用同一规则。

验收使用临时配置与隔离 SSH 服务，覆盖相同密钥的多种换行、首次信任后重读、真实密钥变化拒绝、格式错误区分及其他主机记录保存；不使用用户服务器做实验，也不为修正误报而清空真实 known_hosts。实际通过结果记入修复版本的验证记录。
