# Qt 桌面应用通用开发规范

适用于使用 Qt 开发的桌面应用。本文可独立用于新项目，所列要求不依赖特定产品、已有代码或历史设计。

**内存效率、视觉表现、动画体验为并列的高优先级目标，正确性和稳定性是交付前提。** 每次优化同时检查这几项，资源预算与设计效果共同参与技术选型和验收。

## 使用方式与约束级别

本文作为新 Qt 桌面项目的通用开发基线，配合项目自身的需求、技术选型和验收目标使用。采用 Qt 的其他语言绑定时，按对应工具链落实等价的所有权、线程和部署要求。

| 类型 | 执行方式 |
| --- | --- |
| 通用要求 | 正确性、对象与线程生命周期、输入响应、数据保存及适用的质量验收要求应落实；采用替代方案时记录理由与验证结果 |
| 设计参考 | 组件配色、尺寸、圆角、布局与动画参数作为试稿起点，由项目主题、平台习惯和实测结果确定 |
| 按需能力 | 表格、页签、编辑器、动态分屏、路径导航、查找、终端、托盘、自定义标题栏、透明窗口和多窗口等按需求启用；只对实际采用且声明支持的能力进行验收 |

示例中的白色面板、蓝色主题和侧栏布局不限定最终设计。内存、CPU、启动与帧耗时的合格阈值由项目在目标环境下确定；不能将本文的参考数值或某次示例表现当作所有应用的统一指标。

通用要求不等于要求每个应用都具备本文全部组件。例如，没有文档编辑需求的应用不必增加编辑器、分屏和终端；采用某项能力后，再落实对应的状态、输入、生命周期和验收规则。项目自己的主题规范记录品牌、具体色值、尺寸与允许的差异，功能设计记录实际启用项与交互策略，历史验证记录保留其当时的范围。

| 阅读范围 | 内容 |
| --- | --- |
| 所有项目的基线 | 第 1、2、4、5、6、7、8、9 章及第 3 章总则；其中标明可选的能力按需采用 |
| 常用组件与分区 | 第 3.1～3.13 节：开关、菜单、卡片、按钮、表单、提示、弹窗、侧栏、Frame、图标、表格、下拉框与列表 |
| 内容工作区能力 | 第 3.14～3.17 节：页签、动态分屏、路径导航、内容查找；第 5.2 节定义窗口与浮窗生命周期 |

## 1. 开发目标与技术选型

立项时先明确目标操作系统、最低硬件、显示器缩放范围、预期数据规模及主要使用场景，并为以下项目建立预算：

| 优先项 | 需要确定的目标 | 验证方式 |
| --- | --- | --- |
| 内存与后台开销 | 首次打开、日常使用、重负载、操作后空闲的内存；空闲 CPU 与后台唤醒频率 | Release 版本分场景、多轮测量，记录稳定值与峰值 |
| 视觉表现 | 排版、字体、颜色、层次、尺寸适配、状态反馈及首帧质量 | 真实渲染截图与交互检查，覆盖目标 DPI |
| 动画体验 | 动画用途、时长、缓动、打断行为及目标刷新率 | 实际硬件观察并记录帧耗时与慢帧 |
| 响应速度 | 启动、首次可交互、页面切换、输入反馈、重操作的可感知等待 | 测量耗时，确认有及时且明确的反馈 |

优先采用 Qt 6 + C++ + CMake。选择仍受支持的 Qt 版本分支及其可获取的维护版本，明确支持来源和适用许可，固定编译器、架构、Qt 版本及构建参数。界面技术按需求选择，通过代表性原型验证关键风险；存在多个候选方案时再进行比较：

| 技术 | 适合的界面特征 | 选型时重点验证 |
| --- | --- | --- |
| Qt Widgets | 标准控件较多、桌面交互密集、希望直接控制控件与原生资源 | 样式定制能力、布局和绘制成本、动画实现质量 |
| Qt Quick / QML | 动态布局、动画、过渡及复杂视觉效果较多 | 场景图和纹理占用、渲染后端兼容性、动画帧耗时 |
| Widgets 与 QML 混合 | 存在明确且不能由单一方案合理满足的界面需求 | 额外引擎与渲染表面、输入和焦点、部署复杂度 |
| Qt WebEngine | 功能本身需要网页运行环境 | 浏览器进程、资源占用、启动速度及部署体积 |

原型包含真实字体、目标数据量和核心动画。先满足视觉与交互要求，再以实际测量选择资源成本合理的方案；不根据框架名称推断最终占用。需求明确且风险较低时，不要求为每个候选技术分别实现完整原型。

### 1.1 新项目启动时填写的约定

将以下内容记录在新项目的工程说明中，作为开发和验收依据：

| 项目 | 需要明确的内容 |
| --- | --- |
| 支持范围 | 操作系统及最低版本、CPU 架构、最低硬件、显示缩放与刷新率；Linux 项目按需区分 X11、Wayland 和桌面环境 |
| 技术与依赖 | 界面技术、Qt 模块、编译器、语言标准、CMake 与依赖版本、许可证及必要的平台适配 |
| 视觉与输入 | 主题参数、系统字体或指定字体、目标语言、字号调整、键盘与触控范围、无障碍目标 |
| 资源与响应 | 代表性场景的内存、空闲 CPU、启动、交互与帧耗时目标，以及缓存、并发和数据规模边界 |
| 窗口与状态 | 单窗口或多窗口、是否常驻、关闭与退出行为、需要保留的输入与窗口状态 |
| 数据与交付 | 可写目录、保存及迁移方式、部署形式、更新需求和目标平台验证方法 |

资源目标暂缺测量依据时，先记录基线与待验证目标，交付前确定可复测的合格条件。优先验证字体、DPI、窗口装饰、核心交互及主要数据规模等高影响项，再扩展完整界面。

## 2. 内存与资源规范

### 2.1 默认执行

- 默认一个 GUI 主进程、一个应用对象，共享适合复用的服务与数据。多进程、多 QML 引擎或多渲染环境应有明确理由，并计入资源预算。
- 页面和辅助窗口按使用频率选择延迟创建、复用或卸载。隐藏时停止没有展示价值的动画、绘制和界面计算；必要的后台任务按需求继续。
- 查找、详情等低频辅助面板可首次使用时创建；延迟创建同时覆盖快捷键、焦点、主题、尺寸变化和未创建状态下的空引用保护。不能通过删除用户需要的撤销、历史或编辑能力来替代资源优化。
- 数据与控件树分离，界面销毁后仍能恢复需要保留的输入和浏览状态。状态保存不能反过来长期引用整棵控件树。
- 列表的活动身份、键盘 current 与真实焦点分开管理：键盘切行可同步当前内容，但不能每次强制把焦点转移到内容区。来源内容反向保选需抑制递归信号；选中行操作绑定稳定 ID，焦点变化不重定向已按下的动作。优先复用一组活动行控件或轻量委托，滚动／折叠后更新位置，失焦仍可辨选中项。
- 局部数据变化采用局部更新，避免整页重建、全量复制和反复解析样式。大列表优先使用模型 / 视图及可复用委托，避免为每条记录长期创建完整控件树。
- 图片、字体、图标、网络对象和可复用计算结果统一管理。缓存明确所有者、上限、失效条件及清理时机。
- 高频处理中的不可变规则、解析模板或正则按生命周期共享，避免逐行／逐项重新构建；主题色等可变状态在使用时获取或按需失效。共享前核对线程安全与配置边界，不把全局长期缓存当作无上限容器。
- 大图片按实际显示需求解码与缩放；大文件采用分块处理。控制原始数据、解码结果、缩放副本、CPU 缓冲及 GPU 纹理同时存在的数量。
- 已完成的网络响应、后台任务和临时对象及时释放；日志和历史记录设置容量与轮转规则。
- 使用信号和事件驱动更新。定时器精度与任务匹配，避免高频轮询无变化状态。
- 依赖可见性、焦点或窗口活动状态的视觉计时器由相关事件启停；只为实际需要显示的内容更新，恢复时直接呈现当前状态。隐藏任务面板本身不代表取消任务，任务生命周期见第 5.2 节。
- 内存优化通过减少分配、复制、缓存和无效存活实现；不使用周期性清空工作集来制造较低的显示数字。

### 2.2 按测量结果启用

| 优化项 | 适用条件 | 验收要求 |
| --- | --- | --- |
| 隐藏后卸载控件树 | 页面较大、低频访问，测量表明有收益 | 保留必要状态，处理异步回调，重新打开的延迟符合预算 |
| 释放隐藏窗口的原生资源 | 原生窗口及绘图缓冲占用明显 | 正确恢复句柄相关属性、焦点和输入，反复开关稳定 |
| 缩减图片与字体缓存 | 缓存超过实际复用需求 | 重新加载及重绘不造成卡顿，命中率与峰值合理 |
| 调整字体后端 | 特定 Qt 与系统组合的字体开销明显 | 核对中文、回退字体、复杂文字、Emoji、用户字体和 DPI |
| 修改分配器或平台堆策略 | 分配热点或空闲块保留已被证实 | 比较占用、分配性能、系统兼容性及长时间运行表现 |

缓存大小、资源卸载延迟和字体后端参数根据项目测量决定，不能设置为所有项目统一的固定值。版本敏感的平台参数需要记录支持范围、配置时机和回退方法，升级 Qt 后重新验证。

像素资源估算：单张常见 32 位图像约为 **逻辑宽 × 逻辑高 × DPR² × 4 字节**。1000×700 的逻辑尺寸在 DPR=2 时，一份像素缓冲约 10.7 MiB。实际还可能包含额外缓冲、对齐、纹理和系统开销，因此透明、阴影、模糊等效果也需要进入预算。

## 3. 视觉表现规范

- 实现前确定统一的视觉语言：配色、字体层级、间距、圆角、边框、阴影和图标风格。将它们集中为可维护的样式参数。
- 保持整体风格一致，所有自定义控件覆盖默认、悬停、按下、选中、焦点、禁用、加载和错误等适用状态。
- 同时提供浅色与深色主题时，两态须一致覆盖主窗口、未激活页面、弹层、菜单、表头、页脚、状态面板、查找区、浮窗及之后创建的控件；不能只换内容背景。其他主题和高对比度按声明支持范围落实，组件示例中的浅色值不直接套用到深色主题。
- 主题切换更新语义参数与必要绘制，不重建业务页面、不丢失输入、选择、撤销、滚动、布局或运行任务。项目明确即时应用、确认提交或取消还原的设置策略，并一致持久化主题偏好；恢复设置不应出现错误主题的首帧。
- 文本与背景保持足够对比度，禁用状态、失焦选中行及选中行内的数值和次级文字仍可辨识；重要状态配合文字、形状或图标表达。焦点、选中、当前项与悬停是不同状态，不能仅用同一微弱颜色变化表达。
- 正文、标题、辅助信息、数值与控件文字分别定义字号层级。用户可调整的样式有明确作用域，不能意外影响其他界面的可操作性。
- 文本使用字体度量和布局系统，处理长文本、省略、换行及本地化。覆盖中英文、不同字重和回退字体；自定义字体加载失败时使用可读的默认字体。
- 图标与图片适配高 DPI；同一视觉元素避免同时混用清晰矢量、模糊位图和风格不一致的字符图标。
- 首次显示前完成必要布局、初始样式及尺寸计算，首帧具有完整背景和内容。避免白闪、默认边框闪现和先显示错误尺寸再跳变。
- 设计空内容、加载、失败和内容溢出状态。长操作期间提供反馈，避免用户误认为点击无效。
- 优先复用 Qt 控件的输入、焦点、键盘及无障碍能力，再定制外观。自绘控件需要补齐这些交互能力。
- 使用 QPalette、集中样式表、自绘或 QML 样式时明确边界，避免多套样式机制反复覆盖同一属性。
- 在实际渲染结果上验收排版、抗锯齿、裁剪、阴影和层级；设计稿和代码中的参数不能替代渲染检查。

本章组件按实际需要选用。几何参考尺寸以 Qt 逻辑像素描述；自定义字号另注明 pt 或 px，并与所用字体 API 保持一致，不能将点数与像素数直接互换。字体优先沿用合适的系统设置，尺寸与色值属于可调整的设计参数；阴影等效果接口的参数单位另按 API 定义换算。

背景、正文、辅助文字、主题色、状态色和焦点色采用统一的语义参数，并为适用的主题与交互状态定义取值。参考颜色仍需在最终组合下检查对比度；辅助文字不能仅通过不断降低透明度建立层次。

### 3.1 可复用控件规范：Toggle / Switch

开关由胶囊形轨道和圆形滑块组成。切换时，滑块平滑移动，轨道背景同步渐变。下表提供一套可以独立实现的参考样式；所有尺寸均为 Qt 逻辑像素，可作为统一主题参数调整。

| 项目 | 参考值或行为 |
| --- | --- |
| 轨道尺寸 | 宽 40、高 20，圆角半径 10 |
| 滑块 | 白色圆形，直径 16，上下及端部留白 2 |
| 关闭位置 | 滑块左上角为 (2, 2) |
| 开启位置 | 滑块左上角为 (22, 2)，水平行程 20 |
| 关闭轨道色 | #DCDFE6 |
| 关闭态轮廓 | 浅色轨道方案为轨道和滑块增加可辨的细描边，参考 1 逻辑像素、#737B87；替代配色同样需区分控件边界与滑块位置 |
| 开启轨道色 | #2F6FEB，允许由主题替换，并核对滑块与轨道的对比度 |
| 动画时长 | 180 ms |
| 缓动曲线 | InOutCubic，起止平缓，中段加速 |
| 键盘焦点 | 清晰可辨的焦点轮廓，参考 1 像素主题色描边 |
| 禁用状态 | 使用统一禁用配色并禁止交互；降低不透明度时仍需核对实际背景下的可辨识性 |
| 绘制 | 抗锯齿；圆角、滑块和颜色在不同 DPI 下保持一致 |

实现约定：

- 使用单一归一化进度 p，关闭为 0、开启为 1。滑块横坐标为 2 + 20 × p，轨道颜色使用同一 p 在关闭色与开启色间插值，使位置和颜色保持同步。
- Widgets 可使用 Q_PROPERTY + QPropertyAnimation 驱动进度，再由 QPainter 绘制；QML 可对同一进度使用 NumberAnimation，绑定位置与颜色。不要让每帧更新触发整页布局或创建新的动画对象。
- 用户再次切换时，停止旧动画，读取当前进度作为新起点，平滑移向最新目标。快速反向时不能先跳到端点，也不能排队播放已经过时的状态。
- 初次加载和外部状态同步通常直接设置正确位置，避免打开页面时所有开关一起滑动。同步过程中阻止不应发出的变更通知，防止触发额外写入。
- 对连接、设备等异步操作，开关请求与实际完成状态分别管理：处理中给出短状态、阻止重复提交，成功后与真实状态同步，失败回退并就地反馈。普通界面偏好开关无需强加异步流程。
- 基于标准可勾选控件能力实现鼠标和键盘操作，提供无障碍名称、明确的焦点状态及禁用行为。小尺寸视觉区域可配合较大的外部点击区域。
- 空闲时不运行循环动画；页面隐藏时停止无用动画，再次显示时与真实状态一致。
- 验收覆盖单次切换、快速连点、中途反向、键盘切换、禁用、外部同步及不同 DPI。滑块无跳变、背景不突变、输入反馈及时。

### 3.2 可复用组件规范：托盘右键菜单

需要托盘菜单时，可采用以下风格：**白色面板、小圆角、柔和阴影、紧凑行距、细线分组、浅灰悬停和清晰的状态标记**。主菜单与子菜单使用一致的视觉语言。具体菜单内容由项目定义。

以下尺寸与色值是便于复现该风格的建议值，尺寸均为 Qt 逻辑像素；最终以目标系统、字体及 DPI 的实际渲染效果为准。

| 项目 | 参考值或表现 |
| --- | --- |
| 面板背景 | #FFFFFF，不透明白底 |
| 外轮廓 | 约 8～10 圆角，1 像素浅灰边框，参考 #E6E6E6 |
| 阴影 | 低不透明度的柔和黑色阴影，约 10～16 的扩散范围；避免重影与浓黑描边 |
| 菜单宽度 | 短文本菜单可从约 148～180 起步，根据最长文本、标记和箭头自适应 |
| 菜单行高 | 约 22～26；单行垂直居中，保持紧凑且易点选 |
| 面板上下留白 | 各约 6～8，顶部与底部一致 |
| 字体 | 默认使用合适的系统菜单字体；自定义时可从 12～13 逻辑像素、常规字重起步，并适配用户字号 |
| 普通文字 | 深色，参考 #1F2328 |
| 分组标题 | 次级文字色，参考 #626A76，与普通菜单项文本左对齐；降低强调程度时仍保持可读 |
| 悬停或键盘活动项 | 整行浅灰背景，参考 #EEEEEE；文字保持清晰，不使用大面积高饱和填充 |
| 分隔线 | 1 像素浅灰线，参考 #D9DCE1；横向覆盖内容区，不依赖大段空白分组 |
| 左侧标记区域 | 预留约 24～28 的统一区域；没有图标或标记时，文本仍保持对齐 |
| 右侧箭头区域 | 预留约 16～20；子菜单项显示小号右向三角，与行垂直居中 |

布局与状态约定：

- 菜单采用“左侧标记区—文本区—右侧箭头或快捷键区”的对齐方式，整体紧凑；名称过长时按内容扩宽或合理省略，不能挤掉状态标记与子菜单箭头。
- 将相关操作按语义分组，组内不插线、非空组之间只用一条分隔线。动态省略动作后，不留下首尾线、连续线或空组；Qt 分隔 QAction 不是可执行动作，验证时须识别 `isSeparator()`。
- 短菜单保持平铺，不为分类增加无益标题或子菜单；确需分组标题时使用弱色且不可执行。删除、取消等破坏性或终止动作可集中在末组，具体顺序服从菜单主要用途：以文档关闭为主要用途的页签菜单可把各类关闭放在顶部同组，不要求所有“关闭”字样一律移底。
- 显示、布局、连接控制、剪贴板、数据修改等按真实作用分组。例如清屏是显示操作，中断命令是运行控制，不因同在终端就混为一组。保持原条件、稳定目标、多选范围、确认及取消规则；空白处菜单不得复用旧选择的数据动作，无效或占位节点不得生成空路径操作。
- 快捷键说明放在 Qt 菜单的右侧快捷键列，不用空格拼接对齐。已有独立快捷键注册时，可使用动作文本的 `\t` 列提示而不再次 `setShortcut()`；仅显示确已实现的快捷键，避免增加重复注册或改变控件原输入语义。
- 独立开关项使用勾选符号；互斥选项使用单选圆圈。单选选中态为主题色外圈与实心圆点，参考 #2F6FEB，未选中态使用中灰色空心圆。
- 状态圆点与选择标记分开表达：单选圈表示用户选择，附加的小圆点表示运行状态。圆点约 6～8，可使用灰色、绿色等主题状态色，并配合可理解的文本或无障碍说明。
- 不同类型的标记分别占用稳定位置；同组文本对齐，不能因为勾选、圆点出现或消失而左右跳动。
- 子菜单沿用相同背景、字体、行高、圆角、阴影和状态标记；靠近对应父菜单项展开，面板之间连续可达。空间不足时自动换边并避开屏幕边界。
- 主菜单与子菜单使用同一套活动项样式。指针从父项移入子菜单时保持菜单链稳定，避免穿过狭窄空隙就意外关闭。
- 键盘活动项提供可辨的焦点标记，可采用主题色轮廓；不能仅依赖与面板接近的浅灰填充来表达焦点。

交互及动画的配套约定如下，动画值为设计建议：

- 右键操作只弹出一条菜单链，不重复显示或先闪出其他窗口。点击外部、切换应用或按 Esc 时，按照菜单层级正常关闭。
- 保留方向键导航、Enter 执行及 Esc 返回或关闭；有子菜单时支持左右键进入与返回。
- 悬停反馈及时，子菜单优先沿用 Qt 或平台的标准延迟与指针容错行为。需要定制时，可从约 150～250 ms 的展开延迟开始验证，避免快速扫过时反复闪现。
- 弹出效果优先采用平台标准行为；自定义时可使用约 80～120 ms 的轻微淡入。动画不得改变最终锚点、造成点击区域偏移或延迟关闭，减少动态效果时直接显示。
- 托盘处于系统溢出区域时，验证菜单位于可交互层级，正确处理外部点击和焦点切换，不与系统面板反复争抢焦点。

Qt 实现与资源约定：

- 优先评估 QSystemTrayIcon + QMenu，以 QAction 表示普通或可勾选项，以互斥 QActionGroup 表示单选组。采用可控的 QMenu 样式或绘制来接近参考外观，同时保留标准菜单交互。
- 直接使用平台原生菜单接口时，圆角、字体、阴影和配色主要由目标系统控制，需要接受系统版本差异；完全自定义样式的路线则要补齐焦点、键盘、无障碍和关闭行为。
- 数据变化时同步动作文字、勾选和可用状态；菜单与动作合理复用，隐藏后停止无用的视觉更新。无需为普通菜单单独建立渲染引擎或常驻高频定时器。
- 阴影明确由系统还是应用负责，避免重复绘制。自定义透明面板处理圆角外透明区、阴影裁剪及点击区域，防止出现黑角或透明区域截获点击。
- 验收覆盖不同 DPI、长文本、主子菜单切换、键盘操作、反复打开关闭，以及托盘在普通区域和溢出区域的表现。

### 3.3 可复用组件规范：卡片容器

卡片用于将相关内容组织为独立区域，可采用浅色页面背景、白色卡片、细边框和适度圆角的层次。普通内容卡片以背景和边框建立区分；需要表达浮起关系时再增加阴影。以下为浅色主题参考值，深色主题与高对比度模式使用相应的语义配色。

| 项目 | 参考值或表现 |
| --- | --- |
| 页面背景 / 卡片背景 | #F5F7FB / #FFFFFF |
| 外边框 | 1 逻辑像素，参考 #E1E6EF，避免浓黑或多重描边 |
| 圆角 | 约 10～12，同层级容器使用一致半径 |
| 内边距 | 约 20～24；紧凑卡片可从 16 起步 |
| 卡片间距 | 约 16～20，窄窗时统一缩减 |
| 标题与内容间距 | 约 12～16；标题与右侧操作垂直对齐 |
| 分区 | 可由标题区、内容区和可选操作区组成，以留白或单条细线区分 |
| 阴影 | 普通卡片默认不加；浮层或可拖动卡片按层级使用轻阴影 |

- 相邻卡片保持边缘、标题和主要内容对齐。内容增多时允许自然增高，长文本换行后不覆盖操作区。
- 静态内容卡片保持普通光标；可点击或可选择的卡片提供对应的悬停、按下、选中、键盘和无障碍语义，避免所有卡片看起来都可点击。
- 卡片内使用异色底栏或图片时，显式处理底部圆角和内容裁剪。不能假定 QSS 的 border-radius 或 QML Rectangle 的 radius 会自动裁剪所有子内容。
- Widgets 可使用 QFrame + 布局，通过对象名或组件属性限定样式作用域，避免将卡片边框意外应用到内部标签和输入框。
- 嵌套卡片减少重复边框与阴影；不为大量列表项逐个附加模糊效果。确需阴影时，为其保留绘制空间并测量滚动与重绘成本。
- 验收覆盖长标题、多行内容、异色底栏、嵌套、空内容和窄窗，核对圆角处无越界、边框无叠加、阴影不被裁断。

### 3.4 可复用控件规范：按钮

同一界面使用一致的按钮尺寸、圆角、图文间距和交互状态。主按钮、次按钮与危险操作按钮分别使用语义样式，主题色由统一参数提供。

| 项目 | 参考值或表现 |
| --- | --- |
| 常规高度 | 约 32～40，根据字体与界面密度调整；文字放大时允许增高 |
| 圆角 / 水平内边距 | 约 6～8 / 12～16 |
| 图标 / 图文间距 | 图标约 14～18，间距约 6～8；图标与文字视觉居中 |
| 主按钮 | 主题色实底与高对比度文字，同一操作组保持明确的主次关系 |
| 次按钮 | 中性浅底或白底、细边框，悬停时轻微加深背景 |
| 危险操作 | 采用明确文字和危险色，不仅依靠红色表达含义 |
| 焦点 | 清晰轮廓，参考 2 逻辑像素主题色描边，不改变按钮占位 |
| 禁用与加载 | 保持文字可辨；加载状态保留布局与必要的取消入口 |

- 覆盖默认、悬停、按下、选中、焦点、禁用和加载状态。悬停和按下须可辨，释放后回到指针所在位置应有的状态；选中项继续保留选中标记，不能被 hover/pressed 覆盖。禁用项不因悬停或点击产生启用反馈。主按钮使用相应主题色变化，普通按钮使用中性反馈。
- 状态切换只改变必要的绘制属性，不因边框粗细变化挤动文字或相邻控件。焦点边框与 checked 标记独立于悬停，保留原键盘、tooltip 和无障碍语义；使用 Qt 事件及样式状态，无需为普通按钮增加常驻轮询或无界图像缓存。
- 标准按钮区分鼠标与键盘焦点提示：鼠标不残留外框或原生内层焦点框，键盘保持单层清晰提示，不通过 NoFocus/clearFocus 隐藏问题。已处于键盘焦点的按钮被鼠标点击也应转换提示，popup 返回保留打开方式；checked 使用底色、图标或身份标记，避免常驻外框冒充键盘焦点。若需事件过滤器，先筛事件类型，只在相关按钮模式变化时局部重绘，不影响其他控件焦点。
- 文字长度与加载文案变化时保留合理空间；避免按钮反复伸缩。长文案及本地化以字体度量决定最小尺寸。
- 优先使用 QPushButton、QToolButton 或对应的 Qt Quick Controls。纯图标按钮提供无障碍名称和必要的工具提示，工具提示不作为唯一的含义说明。
- 本节的图文组合适用于需要明确动作文字的按钮；保存、取消、确认及难以单凭图形理解的动作保留文字。紧凑工具栏中语义明确的图标型动作按第 3.10 节使用纯图标，避免所有操作一律去掉文字或一律追加标签。
- Enter、Space 和默认按钮行为遵循控件及平台习惯；不能让不相关的输入操作意外触发默认按钮。耗时操作防止重复触发，反馈及时出现。
- 验收包含鼠标、键盘、快速连续操作、长文案和不同 DPI，核对焦点可见、图文无偏移、点击区域与外观一致。

### 3.5 可复用组件规范：输入框与表单行

表单采用稳定的标签、输入区、辅助说明和校验信息布局。以下为常规密度参考值，最终根据平台字体、字号和本地化结果调整。

| 项目 | 参考值或表现 |
| --- | --- |
| 输入区高度 | 约 34～40，随字体与内容需求增高 |
| 边框 / 圆角 | 1 逻辑像素中性细边框，圆角约 6～8 |
| 内边距 | 水平方向约 10～12，垂直方向由字体度量与目标高度共同决定 |
| 标签与输入区间距 | 约 6～8；标签位于上方或采用统一的侧边对齐 |
| 字段间距 | 约 16～20，同组字段保持对齐 |
| 焦点与校验 | 焦点使用主题色轮廓，错误配合文字说明；状态变化不改变输入区占位 |
| 附加按钮 | 与输入框垂直对齐，图标大小和点击范围与其他按钮一致 |

- 标签始终可辨，不能仅使用占位文字代替标签。明确必填、可选、只读和禁用状态；只读内容按需求支持选择与复制。
- 短字段可采用多列布局，长文本或路径可跨列；空间不足时改为单列，不能通过压缩到不可用宽度维持列数。
- “说明文字 + 右侧控件”的表单行允许说明换行，右侧控件保持对齐且不被挤压。视觉尺寸较小的控件提供足够点击区域。
- 设置页面的数值框与闭合下拉框仅在用户点击启用且拥有焦点后响应滚轮修改。悬停或滚轮本身不得抢焦点；未启用时忽略该滚轮事件，交给父滚动区滚动页面。点击标签、空白或其他区域后退出滚轮编辑，不能只依赖默认焦点转移。保持键盘、无障碍和已展开下拉列表的正常操作；规则限定于设置表单，不改变正文编辑器或终端滚轮。
- 使用 QLabel 的 buddy 或合适的无障碍关联建立标签与输入框关系，保持合理的 Tab 顺序和清晰焦点。
- 动态同步内容时保留合理的光标、选择和滚动位置，避免无变化的 setText 干扰正在进行的输入法组字。
- 校验信息放在相关字段附近，说明问题与修正方式；避免每次按键都弹出模态对话框。错误消失后的留白按统一策略恢复。
- 验收覆盖中文输入法、中英文混排、长路径、选择复制、键盘导航、只读与禁用，以及字体放大后的布局。

### 3.6 可复用组件规范：状态徽标与提示条

状态徽标表达简短、持续的状态；提示条承载需要阅读的说明和可选操作。两者分别设计，避免将长段信息塞入小尺寸徽标。

| 项目 | 参考值或表现 |
| --- | --- |
| 状态徽标 | 紧凑圆角或胶囊形，水平内边距约 8～12，垂直内边距约 4～6 |
| 状态标记 | 可选 6～8 的圆点或统一图标，与文字保持约 6～8 间距 |
| 提示条 | 圆角约 8～10，内边距约 12～16，正文可换行 |
| 层次 | 使用低饱和背景、可辨文字与可选细边框，不让大面积高饱和色压过正文 |
| 语义 | 信息、成功、警告和错误使用统一的颜色、图标与措辞 |
| 操作区 | 与正文保持间距；窄窗时允许换行，不遮挡文字和关闭按钮 |

- 用文字和图形共同表达含义，颜色仅作补充。徽标文字和重要状态不能依赖细小色点才能理解。
- 明确消息的位置、优先级、保留时长和关闭条件。仍有效的错误不能被无关成功提示或普通刷新覆盖。
- 持续状态保持稳定，按需更新；不使用无目的的闪烁或常驻循环动画吸引注意力。
- 页脚或状态栏可承载当前对象、任务进度及持续状态；文字说明具体含义，颜色作为补充。阈值、单位和异常条件由业务定义，不为所有应用规定统一的性能或连接阈值。
- 动态变化尽量局部更新，保持徽标和操作区位置稳定。需要辅助技术感知的变化采用适合的平台无障碍通知。
- 验收覆盖长文案、多条消息、窄窗、无操作和带操作状态，核对颜色对比、换行、关闭和键盘访问。

### 3.7 可复用组件规范：弹窗与模态遮罩

弹窗沿用主界面的字体、间距、按钮和语义配色；主窗口、对话框和菜单的阴影层级协调。平台原生对话框可沿用系统外观，自定义对话框按以下参考样式实现。

| 项目 | 参考值或表现 |
| --- | --- |
| 面板 | 不透明主题背景、细边框；圆角与阴影遵循第 6.1 节的窗口外框约定 |
| 内容宽度 | 简短弹窗可从约 360～520 起步，上限受当前屏幕工作区约束 |
| 内容内边距 | 约 24～32；标题、正文、操作区间距约 12～20 |
| 正文 | 自然换行；长内容允许滚动，操作按钮保持可访问 |
| 遮罩 | 可采用约 20%～40% 不透明度的中性暗色，仅覆盖需要阻止交互的区域 |
| 按钮 | 使用明确的操作文字，排列遵循平台习惯；重要操作提供清晰的取消路径 |

- 根据用途选择模态或非模态，明确父窗口与作用域。Widgets 优先使用 QDialog；使用异步 open() 时处理好结束回调与对象生命周期。
- 打开后焦点进入弹窗，模态弹窗的 Tab 导航保持在其内部；关闭后焦点返回合理的触发位置。具有破坏性后果的操作默认聚焦取消等安全选项。
- 定义 Enter、Esc、关闭按钮和点击遮罩的行为。阻止误操作的弹窗不能因为随意点击遮罩而执行确认动作。
- 同一触发过程避免叠加重复弹窗和遮罩。关闭、取消和父窗口销毁时，一并清理遮罩与临时资源。
- 相对父窗口定位后，再约束到实际屏幕的可用区域。移动、缩放及 DPI 变化后保持内容可访问，不能简单居中到屏幕外。
- 验收覆盖键盘、重复触发、长正文、父窗口移动或关闭、多屏和不同 DPI，核对焦点恢复、遮罩范围与阴影裁剪。

### 3.8 可选布局规范：侧栏与内容区

多页面工具型应用可采用固定导航侧栏与独立滚动内容区；其他应用按信息结构选择合适布局。

- 侧栏宽度可从约 180～240 起步，导航项统一图标、文字及选中标记的对齐。选中态与悬停态有明确区别，并配合可见的键盘焦点。
- 内容区外边距可从约 24～40 起步，分组间距约 16～24。窄窗统一缩减留白，必要时折叠导航，不能挤压正文和主要控件。
- 需要标题、说明和操作时形成稳定的页面头部，同级页面保持一致；如果窗口标题、页签或表头已明确表达当前内容，不再追加同义占位标题或单独工具行。
- 不因参考图存在某项控件就增加搜索、筛选、统计标签或空操作栏。少量内容下没有作用的管理栏可自动隐藏，但保留必要操作的可发现入口，数量变化时稳定恢复；不能隐藏仍有使用价值的信息或让布局反复跳动。
- 明确页面级与组件级的滚动边界，避免多个同方向滚动区域争抢输入。内容增长时提供可见、可操作的滚动入口。
- 验收覆盖最小窗口、长导航文字、键盘切页、内容溢出和字体放大。

### 3.9 Frame 分区边界

- 主要面板、卡片、内部分隔、活动区域及拖放反馈使用集中维护的语义样式参数；各主题分别确定可辨的边线颜色，不能只用接近的底色或留白划分区域。
- 内容区、侧栏、底部面板、footer 等实际存在的主要 frame 在渲染中应有持续可见的边界，参考 1 逻辑像素；footer 的顶部边线应落实在真实承载控件上，不假定它一定是 QStatusBar。
- 相邻区域约定由一侧或共享分割手柄负责边线，避免双重粗边。卡片外框只作用于容器，不向内部标签、布局和任意 QFrame 传播边框。
- 分区边框使用局部对象名、语义属性或组件绘制，不对所有 QFrame 强行描边；布局包装控件和内部标签不自动成为可见卡片。表格卡片的连续表头与内部无网格设计见第 3.11 节，可选动态分屏的方向与回收规则见第 3.15 节。
- 分割手柄可以使用细视觉线与较大的命中区，并提供悬停和拖动反馈。边界规则不得破坏原生顶层窗口外框、标题栏、圆角和阴影。
- 圆角背景、描边和裁切共用外轮廓几何。画笔中心向内缩实际线宽的一半，中心线圆角半径相应减半线宽，避免固定 0.5 内缩在缩放后裁掉外侧描边。整窗 mask 不可截去抗锯齿或边框；需要区域回退时包含抗锯齿包络，并随尺寸、DPR 和界面缩放更新。
- 圆角卡片的 header、viewport、滚动条等子内容不能盖住外框。可用内留边、局部内容裁切，或单个鼠标穿透且不获焦的轻量描边层补齐四角；仅已有语义容器启用，不对普通布局加框，不引入周期计时器或位图缓存。进程表保持表头与表体连续的大卡片，不为修角添加内部网格。
- Qt 客户端圆角菜单继续使用 QMenu 的输入、键盘、子菜单和关闭语义。与 Windows 额外 DWM 圆角冲突时，只对相应 popup 使用有平台保护的公共属性，保留主窗/对话框原生标题栏和高对比度回退；失败路径不能留下过时 mask。验收明确区分 offscreen、隐藏 Windows HWND 客户端截图、DWM 合成桌面和真实多屏；DPR render 仿真不能表述为多屏实测。
- 验收使用真实字体与实际控件渲染，覆盖明暗主题、活动状态、空内容及目标 DPI；代码中存在 border 声明不等于边界可辨。

#### 共享边与缩放接缝验收

- 为每条共享边明确唯一绘制者，结构工具带的边线包含在声明高度内，不能额外追加1px使同级标题错位。拖动命中宽度与可见线宽独立；使用 Qt 的扩展命中时应实际拖动验证。
- 同级标题、页签和右侧动作区使用同一可缩放度量与字体基线。主结构贴边，内容留白在内部，不用不一致的外边距承载结构底线；T形/十字交点必须连续，圆角仅用于确有独立边界的卡片或浮层。
- 背景和文字样式限定到实际组件，侧栏 viewport 与父区域一致，标签默认透明。避免通用 QWidget 填色覆盖选中整行或圆角子内容；覆盖层必须不获焦、不截获鼠标且随父对象释放。
- 验收使用真实业务控件渲染，检查明暗、多个应用倍率以及整数/分数DPR下的接缝、活动页签实际范围、边框四角和拖动命中。记录逻辑坐标、渲染倍率和仿真方式；代码常量检查不能替代图像与输入检查。

### 3.10 纯图标工具按钮

- 工具栏和活动栏中适合图形表达的图标型动作采用统一矢量资源或矢量绘制引擎，不用 Unicode 字符或 Emoji 充当图标。使用纯图标保持紧凑，必要时用 tooltip 辅助解释；保存、取消、确认等表单文字动作及下拉选择保留清楚的文字语义，适用范围与第 3.4 节一致。
- 图标、主题颜色、尺寸与状态集中管理。工具栏图标可参考 18～20、点击区域 28～32；活动栏图标 24、点击区域 40～44；页签关闭图标 16、点击区域 22～24，单位均为逻辑像素。
- 图标按实际可见笔画的光学大小验收，不能只检查 iconSize 数值；独立图标应充分使用画布，复合图标的角标可保留较小尺寸。
- 每个纯图标按钮提供当前界面语言的操作 tooltip 和无障碍名称，中文界面使用中文；提示只标注确实已实现且适用于当前平台的快捷键。按钮保持键盘可达，选中项具有固定的可见标记。tooltip 不能代替按钮本身的可识别图形、焦点和无障碍语义。
- 主动作另带方向等选项时，使用可发现的菜单箭头或明确菜单入口，不要求用户猜测长按或右键。可以适当加宽点击区容纳箭头，主体和菜单的命中范围清楚区分，图标与同行文字保持光学居中。
- 覆盖禁用、悬停、按下、选中和键盘焦点状态；主题与 DPI 改变后更新图标且保持清晰，不重新建立页面或业务会话。
- 同一个按钮用于面板最大化／还原时，保持原四角图标的形状，使用选中背景／边框表达最大化状态；还原后取消选中，并同步 tooltip、无障碍名称和实际布局状态。该规则针对应用内面板，不改动操作系统原生窗口按钮。
- 实际渲染验收应包含支持的明暗主题、常用图标、工具提示、窄窗口和目标缩放；缺少目标语言字形的截图不能作为样式验收结果，中文项目需核对真实中文字体。

### 3.11 可复用组件规范：数据表格与刷新状态

适用于需要表格展示的数据，不要求每个页面使用表格。可浏览整行的记录表与可编辑单元格的表格应分别确定选择、焦点和键盘策略。以下是紧凑卡片式记录表的设计参考，数据密度和字号以可读性为准。

| 项目 | 参考值或表现 |
| --- | --- |
| 整体容器 | 一张大卡片，约 8 逻辑像素圆角、1 逻辑像素清晰外框 |
| 表头 | 独立语义背景、可读文字与可排序标记；只在整卡上方形成圆角，下边直，与正文连续相接 |
| 正文 | 相邻行用轻微交替底色区分，默认无需内部横线、竖网格或表头底线 |
| 选择 | 选中背景优先于交替底色；活动与失焦选中均可辨，焦点提示不改变行高 |
| 列布局 | 主要名称或描述列按需伸展，状态等短列紧凑；数值列可调宽，不能被剩余空间分配挤压 |
| 字体与数值 | 字号遵循正文体系；紧凑桌面表可从约 13 逻辑像素试稿，右对齐数值并明确单位、精度与空值含义 |

- 表头与正文属于同一外卡片，不把表头另画成四角圆的 pill，不留悬浮间隙。确有阅读定位或列宽拖动发现性需求时，可在表头列间增加可辨的短竖分隔；正文仍可保持无网格，不能把“默认无需分隔”当作禁止所有表头分隔的绝对规则。
- QSS 圆角未必裁切 header、viewport 与滚动条。可采用轻量外卡片、少量留边、局部裁切或绘制解决，保持圆角连续，不让直角子控件盖住外框；不要为裁角增加大面积透明层或每行图形特效。
- 名称省略时提供完整 tooltip；数字、单位和短状态不随意拆行。窄视图优先在表格内部横向滚动，不缩小到无法辨认，不静默丢列。避免用空白状态列吃掉所有余宽；用户调过的列宽、列顺序按产品策略保留。需要跨次恢复时按视图身份及列模型版本独立持久化，校验列数与合理宽度；紧凑概览不覆盖完整视图偏好，刷新数据不触发重新分配用户宽度。
- 表头说明可以解释单位、来源或统计口径。仅作补充解释的短说明适合 tooltip；关键决策信息仍应可见，不把必要警告藏进悬停提示。无需为每张表添加重复标题与底部说明行。

动态刷新使用稳定业务 ID 识别记录，不能使用行号、当前排序位置或显示名称作为身份。身份范围由数据源保证；若标识可能复用，应采用业务提供的代次／复合键，或明确快照范围的限制，不能宣称解决了数据源没有提供的信息。

1. 刷新前保存选中 ID 集合、current ID 与列、焦点所在控件、排序列与方向、横纵滚动、用户列宽等需要保留的状态；必要时用可见记录 ID 作为滚动锚点。
2. 按 ID 增量更新数据。复用仍存在的模型记录或 item，仅移除消失项、增加新项，避免每次清空重建；身份 role 与用于显示、数值排序的 role 分开。
3. 更新使用正确的模型增删／移动通知；确需暂停自动排序和重绘时只限受影响视图，并保证所有结束路径恢复。不能通过阻断模型协议必需的信号破坏代理模型、选择模型或辅助技术状态。
4. 更新后恢复原排序，再按 ID 恢复仍有效的多选及 current 列，恢复滚动与列宽；超出新范围的滚动值按合法范围限制。不要因恢复 current 就自动滚走视图，也不要重置焦点或中断单元格编辑。
5. 消失记录取消自身选择，不能让占据同一行的新对象继承选择。过滤后／分页中／前若干项的子视图明确可见选择策略，离开当前样本的 ID 不自动转选替代行；空快照按约定清空且可恢复。

验收连续多个快照的重排、排序值变化、多选部分退出、新 ID 替代、空快照、子视图与横纵滚动，核对 item／模型身份和输入状态，不只比较刷新后行数。主题验收包含交替色、失焦选中、禁用文字、窄列数值及圆角接缝。

数据视图可用语义颜色区分数值类型，但标签仍保持中性层级，且同一类型的数值、图例、曲线保持一致。选中态单独核对文字对比，不能只在默认背景上验收；线图同时用线型或文字标识区分。自绘监测摘要提供随真实值更新的无障碍名称/描述；未知、未就绪与真实零值应区分，局部数据缺失不阻断其他已取得的信息。图表样本和重绘保持有界，不为视觉展示伪造运行数据。

### 3.12 可复用控件规范：ComboBox 与下拉列表

单值选择优先使用 QComboBox 或相应 Qt Quick Controls，保留原生 item model/view、键盘、焦点、无障碍与信号语义。可编辑 ComboBox 另定义输入、校验和补全策略，不能用只读选择框的取消规则覆盖用户自由输入。

| 项目 | 参考值或表现 |
| --- | --- |
| 选择框 | 主题正文与底色、1 逻辑像素细边、约 5～6 圆角，覆盖 hover／focus／disabled |
| 箭头 | 右侧独立小 chevron 与稳定留白，不与文字或清除按钮重叠 |
| 弹层 | 可辨的主题细边、约 6 圆角、少量内边距，按原生层级覆盖下方内容；可从四周 4～6 留边试稿 |
| 宽度 | 至少容纳选择框宽度，长文本可适量加宽，但受所在屏幕可用区域约束 |
| 位置 | 优先紧贴框下方，参考 4 逻辑像素间隔；下方不足且上方更合适时向上，不能覆盖选择框本身 |
| 高度 | 依据可用空间与合理可见项数限制，超出后滚动；当前项可见但不为对齐当前行而上移遮住选择框 |

- 已提交值与弹层中鼠标／键盘预选值分别处理。预选使用可见 hover／焦点态，已提交项按设计保留勾选或其他可辨标记；不以移动预选代替提交。
- Enter 或点击合法项提交并关闭，按原生信号契约发送：值变化通知在实际变化时一次，用户激活信号也不因自定义逻辑重复发送。Esc 取消未提交预选并关闭；再次打开先从已提交索引恢复 view current／selection，再滚入可见，不能沿用上次取消的预选。
- 优先使用原生容器、列表委托和局部样式，小共享子类只补足主题与几何；避免重造整套 popup。改变几何或自绘边框时仍需保持键盘导航、滚动、输入法与无障碍操作。
- 使用当前锚点所在屏幕的 availableGeometry，包含边框与内边距计算。支持负坐标和混合 DPI；空间不足时选择较充足一侧并限高滚动，不能越界或盖住触发框。极小工作区不足以显示可操作列表时应明确采用受限平台回退，不伪造可用面积。
- 父窗口移动、隐藏、尺寸变化、屏幕工作区改变或触发控件销毁时，关闭或按已定义策略重定位弹层；处理相关对象事件即可，不通过全局轮询追踪位置，不能留下脱离选择框的 popup。
- 两主题都检查真实容器外框、圆角和子视图留边；样式声明不代表私有 popup 实际会使用该绘制。颜色沿用统一语义参数，深色列表不得残留浅色底。
- 不因示例图包含搜索、多选或分组就无条件增加功能；简单单值选择保持紧凑。条目数量确实影响查找时，再按需求引入可编辑或搜索能力并补齐语义。
- 验收靠后当前项、窄窗口／长文本、屏幕边缘、向上／向下展开、有限高度滚动、Esc 后重开、鼠标／键盘提交次数、父窗口移动与主题变化。

### 3.13 可复用交互规范：列表选择与批量操作

适用于允许选择记录的列表、树或记录表；若为单选导航、开关集合或单元格编辑，采用与其语义一致的交互，不强套文件管理器模型。

- 记录型列表整行可单击选中，双击或 Enter 打开／执行主动作时保持规则一致。需要多选时支持平台相应的 Ctrl／Command 增减与 Shift 连续范围，范围基于当前可见顺序；键盘焦点、current 与选中集合分别维护。
- 需要类似文件浏览的批量选择时，可从空白区域开始拖动框选。明确它与滚动、拖动记录、展开树节点的手势边界；按 Esc、离开合法范围或捕获丢失时清理临时反馈。
- 不要求所有列表配复选框。复选框适合持久的勾选集合、触控或明确的批量勾选工作流；普通记录选择可以使用标准选中态。采用复选框时区分“勾选”和“当前选中”，不能让两者含义冲突。
- 右键已选中记录时保留多选，并让适用菜单动作作用于当前选择集；右键未选中记录时明确选中该记录再操作。空白处菜单只提供当前位置或全局动作，不暗中复用无关旧目标。批量动作可显示数量，混合可用性要解释禁用或部分执行策略。
- 存在重命名功能时提供 F2 或平台约定的入口及右键动作，保留当前项焦点；处理同名、非法名称、权限与取消。名称变化按稳定 ID 同步相关视图，不让未保存内容失去归属，不静默覆盖其他对象。
- 删除等破坏性操作执行前显示确认弹窗，列明目标、范围和不可恢复后果，提供明确的取消入口；取消不得开始执行。批量处理去重重叠对象，并说明未保存内容、部分失败及开始执行后的取消边界。危险操作不用含糊的“确定”代替具体动作，也不依靠红色作为唯一警示。
- 树形数据的新增／删除按稳定路径或业务 ID 局部同步受影响父节点，保留其他分支的展开、选择、焦点与滚动；类型变化时清理不再适用的子树，部分失败也同步已受影响区域。异步结果关联请求 ID 与导航代次，不能保存可能已被删除的裸 item 指针。
- 按需使用树内新建占位时，菜单动作固定捕获目标目录，不随选中变化改变。明确空名、Enter、失焦和 Esc 的提交／取消策略；若约定非空失焦提交，点击导航或替换草稿入口也须先完成原目标提交，不能先清草稿再等待延后 FocusOut。非法／重名保留可修正输入，创建不得静默覆盖。占位不参与打开、删除、上传落点或普通记录选择；编辑区行高与剩余行宽足够，不被相邻列裁切。
- 验收单选、多选、反向范围、空白框选、右键目标、键盘重命名、刷新中选择与批量失败；选择样式与第 3.11 节一致，不能在失焦后难以辨认。

### 3.14 按需布局规范：紧凑页签与所属组操作

多文档或多内容应用可使用页签组；普通单页应用不必增加页签。每组页签、操作和内容拥有清楚的归属。

- 已有原生窗口标题或页签表达当前内容时，不重复显示同义品牌、占位标题或“内容编辑”工具行。需要常用组操作时优先放在该组页签行右侧，同排垂直居中；终端等其他独立组件的管理行是否保留按其实际需求决定。
- Widgets 可用 QTabWidget 的 cornerWidget 或等价组 header；给工具区独立留出宽度，按钮的点击区与页签滚动按钮不重叠。长标题省略并提供完整 tooltip，溢出仍可滚动、键盘切换和访问全部页签。
- 页签与 corner 操作必须共用一个 header 底边绘制者。声明高度包含预留边线；原生 tab/corner 只占内容区，不能另外画底边或从未经约束的 sizeHint 增高。页签为空、溢出滚动、分组增删时，内容区起点和共享边契约也必须成立；用真实像素和命中验证，不能用局部上下偏移掩盖重复绘制。
- 统一 QMessageBox 外观时保留原生布局对象及按钮、标签、角色、默认/退出动作和 open/exec 信号。仅重排布局项；Qt 重建内部布局后重新捕捉。验证显示后改文案/复选框/详情、换肤缩放、重复显示和父对象销毁，不能靠拦截事件掩盖已删除的内部引用。重排或重新设父对象后须验证按钮实际可见、默认状态和 Enter 的结束结果，而非只检查默认指针；本地化标准文案不得覆盖业务自定义文案或改变角色。无空格长路径须验证实际绘制的行宽和末尾可见性，不能仅测量另一个可换行的文档副本。
- Windows 圆角 popup 的半透明需在创建原生窗口前配置合适标志和透明清除；DWM 圆角设置成功不代表 alpha 合成正确。使用独立受控背景先验证弹出前底色，再比较动画中及结束后真实桌面合成的四角与该底色，不能仅排除黑色；只截取测试窗口所属区域。保留不能使用 alpha 时的轮廓回退。
- 点击某组按钮或菜单必须作用于该组，不依赖过期的“上次活动组”；需要先激活目标组时显式处理。合并、关闭等跨页动作明确目标组与范围，并按当前状态更新禁用态。
- 支持页签排序时提供拖动插入位置反馈；在不改变对象身份的前提下更新顺序，保留各页数据、撤销、选择和滚动。页签栏工具区不算插入落点，拖入该区拒绝并清除预览。
- 按需求提供关闭当前、关闭其他、关闭右侧、关闭已保存、全部关闭等菜单，菜单文字和作用范围一致。关闭已保存只涉及无需保存的目标，批量关闭不能越过其声明的组范围；固定页可不提供关闭入口。
- 单页关闭、批量关闭、浮窗关闭和应用退出共用保存保护。未保存项提供保存、放弃、取消；保存失败、冲突或保存后又出现新修改时不得把未保存内容当作已保存关闭。批量流程定义遇到取消时保留哪些页面、是否允许已完成项先关闭，不隐瞒部分完成。
- 菜单、拖放和保存确认可能进入异步或嵌套事件循环；绑定目标使用有上下文的回调与 QPointer 等保护，必要时延后清理正在交互的组。不要捕获随后可能被移除的裸组引用。
- 原生关闭按钮被自定义按钮替换时，遵循第 5.1 节核对两侧旧控件所有权。验收长页签、小窗口、多个组、按钮归属、排序、各种关闭与取消／失败路径。

### 3.15 按需能力规范：动态分屏、拖影与内容迁移

需要并排处理多个内容对象时使用动态分组。应能在不同组显示多个不同文档或视图，而不是只复制同一份内容来演示分屏；是否另支持同文档多视图由产品明确。

- 连续左右拆分在同一排增加相邻列，连续上下拆分沿同一列增加相邻行，不随组数自动交替横竖方向或变成网格；只有用户显式改变方向才形成对应嵌套布局。可使用动态 splitter 树表达分组，不限定为两个固定容器。
- 新组只划分目标组的原有空间，尽量保持其他组比例；如果预览为目标半幅，放置结果也应落在该半幅。窄窗口可以限制合理最小尺寸、允许内部滚动或提供恢复布局，不悄悄改变用户选择的排列方向。
- 移空或关闭空组后回收该组，只有一个子节点的容器按需折叠，由剩余区域填满；是否保留最后一个空工作区由产品约定。清理发生在安全的迁移／交互阶段，不销毁当前信号发送者或悬空菜单目标。
- 分屏需要迁移现有页时，内容不足应禁用或明确无操作；若产品支持空分组或同文档多视图，应明确创建含义，不为单页操作偷偷新建业务对象或复制文档。
- 达到系统拖动阈值后显示小页签拖影，来源页在确认放下前保持完整。页签栏显示插入线，内容中心显示合入预览，边缘显示对应方向与范围的预览；只有真正命中允许区域才显示可放置反馈。
- 判断页签落点时同时校验 x／y 与实际 tabBar 矩形，不把同行工具、空白无效区或其他产品实例误判为页签栏。MIME 验证来源、所属区域和对象有效性，不凭外部字符串接受任意指针或跨范围迁移。
- 预览不截获必要输入、不改变正文布局，结束、Esc、离开、捕获丢失、来源／目标销毁均清理。拖出窗口仅在明确合法的放下结果且产品支持浮窗时执行；取消不能误生浮窗，来源状态应保留。
- 移组、合并或浮出优先复用原视图／模型，保留内容、撤销、光标、选择、滚动及运行状态；不要把布局变化当作重新打开文件或重新建立业务任务。需要通知底层尺寸时，合并到最终有效布局，避免迁移过程的临时尺寸损坏内容。
- 新内容进入活动组，组操作归属遵循第 3.14 节。浮窗明确来源与收回目标，关闭、收回和退出按第 5.2 节声明策略，不把任何单个产品的浮窗规则当作唯一方案。
- 验收连续三组及更多组、两种明确方向、移空首／中／末组、合并、多个不同内容、组内排序、预览与结果一致、取消／失效，以及迁移前后的对象身份和编辑状态。真实原生拖放与离屏合成事件分开记录覆盖范围。

### 3.16 按需导航规范：路径面包屑与地址编辑

适用于文件路径或其他可逐级导航的地址。层级语义、根节点和分隔规则由目标空间定义，不假定所有项目使用同一种路径格式。

- 面包屑使用紧凑可点击的各级名称与小号装饰性 chevron，当前层级适度强调；每级点击到其明确目标，tooltip 可给完整地址。装饰箭头不参与键盘焦点，确有导航菜单的箭头则提供相应按钮语义。
- 保留真实大小写、空格与特殊字符；例如名称中的 `&` 不应变成快捷键下划线或被吞掉。根路径只显示实际根标记，不能重复拼接分隔符。
- 长路径按可用宽度省略中间层级、保留当前层级与有用的邻近层级，省略标记独立可辨；完整地址始终可通过 tooltip 或编辑模式获得。省略本身若可操作，明确展开方式；不能用过宽名称撑开侧栏。
- 路径输入模式以当前已提交地址初始化，提供显式入口与适合的选择／焦点状态。采用确认后导航模式时，Enter 校验并显式提交；Esc 或失焦取消尚未提交的编辑，退出输入模式并恢复当前已提交路径，不自动导航。
- 上述失焦取消仅适用于明确设计成这种模式的路径编辑框，不能推广为所有表单失焦丢输入。提交与切回显示模式的顺序要避免 FocusOut 把刚要提交的值覆盖；异步加载成功后更新已提交地址，失败保持可理解的当前位置与重试反馈，不能伪装已经到达。
- 需要历史导航时提供返回、前进、刷新，以及实际有意义的上一级／起始位置入口。返回／前进遍历有效历史，新导航成功后按策略截断前进分支；刷新当前地址不重复增加历史。无可用历史时禁用相应入口，失败与取消不污染当前位置和历史。
- 验收根路径、多层／长名称、特殊字符、点击目标、输入 Enter／Esc／失焦、加载失败与历史边界。测试模拟路径跳转不等于已验证真实数据源导航。

- 路径采用面包屑时，可将框内空白的左键点击作为编辑入口；目录段和分隔命中需明确区分，预留可点击空白，右键不切模式。编辑初始化已提交路径并全选；Enter 显式导航，Esc／失焦恢复已提交路径，不自动提交未确认输入。两态高度、边框与可访问性一致；路径快捷键限定到适当资源区域，不能截获终端／编辑器的同名组合键。

### 3.17 按需组件规范：内容查找与替换浮层

文档、日志或其他可搜索内容采用 Ctrl+F／平台标准 Find 时，将动作路由到当前内容视图。替换只在可编辑内容中按需求启用，不要求所有可搜索页面提供编辑功能。

- 查找区可采用固定在内容容器上方的覆盖式浮层，例如内容右上角；不夹在页签与正文之间额外占一行，不随文本或列表内容滚动。以相应 viewport／内容容器坐标定位，容器 resize、分屏、浮出后重新约束到可见范围。
- 输入和按钮不遮住自身命中范围；窄容器调整宽度与内部布局，保证查找、关闭和必要操作可访问。定位匹配项时尽量使结果不被浮层覆盖，不能为固定浮层锁死正文滚动。
- 明确 Enter／Shift+Enter 的下一处／上一处、Esc 关闭并回到来源内容焦点；可编辑场景需要时提供 Ctrl+H 或明确入口展开替换。重复调用复用面板与合理查询状态，焦点不会错误跳到另一组。
- 搜索选择与普通选择的样式、空查询、未找到、循环查找及大小写等选项按实际需求定义；不因参考图有大量选项就全部加入。替换遵守只读权限与撤销规则，批量替换能形成合理的撤销单元，失败不丢内容。
- 面板可首次调用时创建，关闭通常只隐藏或按已定义策略回收，所属内容销毁时一起释放；生命周期细节见第 2、5 章。隐藏浮层不能遗留全局快捷键抢占其他控件。
- 验收多个视图／组与浮窗的焦点归属、独立滚动、窄布局、重复打开关闭、主题变化、替换与撤销及内容销毁；不能只核对查找框是否出现。

## 4. 动画与响应规范

### 4.1 动画设计

- 动画用于表达状态变化、空间关系和操作反馈，与整体视觉语言统一。按钮、开关、展开收起、页面过渡等按实际交互设计一致的反馈。
- 动画参数集中管理，包括时长、缓动、起止状态和打断策略。可用微交互约 100～180 ms、面板过渡约 180～300 ms 作为试稿起点，最终按距离、内容和实测体验调整。
- 用户连续操作时，动画从当前视觉状态平滑转向最新目标；重复触发不堆积动画队列，反向操作不跳回旧起点。
- 动画期间输入、命中区域和最终布局保持一致，不能产生可见按钮点不到、透明区域挡输入或尺寸结束后跳变的问题。
- 页面隐藏、窗口最小化或对象销毁时停止不需要的动画。再次显示时呈现正确状态，避免补播隐藏期间积压的变化。
- 参考系统减少动态效果偏好，并在需要时提供减少动画的选择；效果减少后仍保留清晰的状态反馈。

### 4.2 动画实现与性能

- Widgets 优先使用 QPropertyAnimation 等 Qt 动画机制，QML 优先使用属性动画、状态与过渡；避免用高频定时器手写固定像素步进。
- 根据真实经过时间进行插值，避免把速度绑定到某次定时器回调次数。支持高刷新率时，在对应设备上核对速度与流畅度。
- 主线程动画路径不进行网络等待、文件读写、字体加载、大图解码或重计算；动画资源在合适时机准备。
- 动画优先改变绘制属性或局部区域。涉及布局、复杂路径、全窗透明度和模糊时，测量每帧开销，避免反复触发大范围布局和离屏分配。
- Qt Quick 中优先利用场景图适合的变换与不透明度动画，按需要评估渲染线程动画；使用图层和离屏效果前计算额外纹理成本。
- 动画对象和信号连接可复用，结束与取消路径明确。缓存只覆盖实际受益的内容，动画退出后释放临时资源。
- 60 Hz 的一帧约 16.7 ms，120 Hz 约 8.3 ms，布局、绘制和合成需要共同满足目标帧预算。既观察平均表现，也记录慢帧和输入延迟。
- 发生卡顿时先分析主线程阻塞、布局、绘制、资源加载及分配热点，依据结果降低单帧工作量，同时复核视觉效果。

普通操作及时产生可见反馈；耗时任务异步执行并展示适合的进度或忙碌状态。动画时长不作为人为延迟业务完成或阻塞用户输入的理由。

## 5. 架构、线程与对象生命周期

- 分离数据模型、服务、界面和平台适配。窗口只负责展示与交互，公共业务状态与可复用服务集中管理。
- QObject 采用明确的父子所有权，其他资源使用 RAII；避免同一对象被多种所有权机制重复销毁。
- 异步连接和延迟回调指定 QObject 上下文；跨界面生命周期引用使用合适的弱引用机制，例如 QPointer，并在使用前确认有效。
- GUI 只在主线程操作。工作线程负责耗时任务，结果通过合适的信号或队列传递；QObject、定时器和网络对象遵守线程归属。
- 界面关闭时明确任务是否继续、取消或转交；迟到结果不能修改已销毁对象，也不能覆盖更新的状态。
- GUI 线程不执行阻塞等待，不依靠反复调用 processEvents 维持表面响应；同步和重入问题通过清晰的状态与异步流程处理。
- 定义程序关闭、后台运行和退出的语义；单实例、常驻及多窗口策略按需求决定。
- 关闭流程先停止接受新工作，再按需要取消或收尾已有工作。工作对象在所属线程按生命周期销毁，线程结束后再释放相关资源；不把强制终止线程当作常规退出方式。取消、超时与重复关闭路径均需稳定。

### 5.1 控件替换、所有权与延后回收

- 隐藏不等于删除，从布局移除也不必然转移或结束所有权。对 setWidget、setTabButton、removeTab、take 类 API 等逐个核对项目所用 Qt 版本的文档，必要时阅读对应实现，明确旧控件是隐藏、重设父对象、返回调用者还是销毁；不能凭名称推断。
- 替换原生控件时先识别旧对象及其所有者，再安装新对象；API 未负责销毁且业务不再需要的旧对象，应在安全时机释放。例如 QTabBar::setTabButton 可能只隐藏被替换按钮，当前 tab 指针不再指向它，后续 removeTab 不会代替清理这批旧对象。需检查平台原生按钮可能位于左侧或右侧，避免只验证一种样式。
- 遵循父子所有权与当前调用上下文选择直接销毁或 deleteLater，不对仍被 Qt 使用、已转交其他容器、需要复用或已由其他所有者负责的对象盲目 delete。将销毁连接到可靠上下文，防止重复清理和悬空引用。
- deleteLater 依赖对象所属线程的事件循环及 Qt 的延后删除语义；嵌套菜单／对话框／拖放循环、线程退出时机需要核对。不能以调用了 deleteLater 代替实际销毁证据，也不能在生产流程中用无界 processEvents 循环强迫回收。
- 页面迁移的 reparent、布局移除和容器清理与“关闭内容”分开处理。控件、文档、委托、定时器、快捷键、辅助窗口与服务分别明确归属，临时状态不因父关系变化而成为长期孤立对象。
- 共享不可变计算规则与按需创建面板遵循第 2 章；共享对象不得持有不必要的页面引用。验证首次创建、未创建时关闭、隐藏重开、主题变化与最终销毁，不以懒加载引入新的生命周期漏洞。
- 回归以真实生产入口反复创建／替换／关闭并核对对象数、弱引用销毁和必要资源计数；记录合理保留对象的目的与上限。测量方法见第 8.1 节，不仅观察某次任务管理器数字。

### 5.2 窗口、浮窗与后台任务的语义

项目应在实现前区分以下操作，并按产品目标选择具体策略；它们不是同义动作。关闭一定退出、最小化一定进托盘或切换页面一定隐藏浮窗，都不是所有应用的通用要求。

| 操作 | 需要定义的行为 |
| --- | --- |
| 最小化／还原 | 按平台处理可见与激活状态，保留内容；是否在最小化时降低视觉更新频率，以及还原后的焦点与位置 |
| 隐藏面板／切换页面 | 保留必要状态与恢复入口，停止无价值的视觉工作；已开始的后台任务默认不因展示面板隐藏而被取消 |
| 关闭页签／文档 | 结束该内容或收回到其他容器的明确策略，未保存保护、资源归属与正在运行任务的去向 |
| 浮出／收回 | 迁移同一内容的归属、目标组及布局，不自动重载数据或创建重复业务任务 |
| 关闭浮窗 | 明确是关闭文档、收回、隐藏还是退出独立窗口；用标题、按钮和菜单解释策略，不让关闭图标产生意外结果 |
| 关闭主窗口 | 明确退出、转后台或仅关闭当前工作区；常驻需有可发现的恢复和真正退出入口，托盘按需实现 |
| 退出应用 | 汇总适用的未保存内容和未完成任务，允许取消或按策略完成收尾，结束所属窗口、线程与服务 |

- 窗口归属与业务归属分别明确。浮窗应标识当前文档或工作范围，提供有意义的返回／收回入口；是否随所属页面切换而隐藏由产品决定，保持一致并验证，不能让用户误以为内容已关闭。
- 顶层浮窗按其用途提供平台常见的移动、缩放、最小化、最大化和关闭能力，模式窗口只提供有意义的操作。必要控件可访问，内容与标题随业务身份正确更新。
- 主窗口关闭、拥有者销毁、浮窗独立关闭与跨窗口迁移均遵循同一保存保护；不因窗口层级不同绕过保存失败或取消。多个窗口显示同一对象时明确共享状态及最后一个视图关闭的含义。
- 隐藏进度或任务面板不取消已启动任务；取消、暂停、重试、关闭任务与隐藏界面分别有明确入口和反馈。任务可能继续时提供可发现的状态与恢复路径；退出需解释任务是否停止、等待还是转交其他进程。
- 视觉恢复不代表业务恢复。持久化布局、草稿或历史不意味着能恢复已结束的进程／任务；恢复能力按真实后端支持声明。保存必要状态时避免间接保留整个旧窗口树。
- 菜单、确认框和异步保存期间发生重复关闭或所有者销毁时，清理流程可安全重复，取消不破坏已有内容；核对关闭后焦点回到合理的仍存活窗口。

传输速度由实际 I/O 所有者按一次任务尝试计量：累计成功的 payload 字节，目录跨子项共享累计，已跳过不算；单调时钟从真正开始到结束，明确枚举／提交等耗时口径并排除排队和显式暂停等待。实时使用有界近期区间差值，暂停前后重置样本，终态强制上报短任务最终数值；平均采用累计字节／有效耗时。失败、取消、全部跳过与零字节准确标记，从头重试清空旧尝试，不把当前子文件 offset 当目录总量。统计对象随任务历史一起释放，无需常驻轮询或无界样本缓存。进度与速度并存，总速率方向与活动任务一致，终态清除遗留实时值。

需要展示后台任务时，可按需采用不抢焦点的角落进度面板，具体位置由项目布局决定。紧凑任务行显示名称、进度和必要操作，批次按需展开；没有实际查找需求就不增加名称搜索或状态筛选。失败展示可理解的原因，重试、暂停、继续、取消分别定义能力和结果；从头重试不能称为断点续传，无法暂停的任务不提供误导入口。隐藏面板与取消任务分离，沿用上表及本节的任务生命周期规则。

## 6. DPI、布局与平台交互

- Qt 布局、尺寸及输入使用逻辑坐标。与原生 API 交互时明确逻辑坐标和物理像素，在平台适配层转换，避免重复缩放。
- 优先使用布局、字体度量和合理的最小尺寸。处理内容增长、字体变化、窗口缩放和本地化，不依靠固定坐标维持整体排版。
- 图像正确处理 devicePixelRatio。多屏场景允许负坐标和屏幕间隙，按实际屏幕的可用区域放置窗口。
- DPI、分辨率、工作区或屏幕连接发生变化时，重新校准布局和窗口位置；恢复的位置应在可访问区域内。
- 使用与 Qt 高 DPI 支持相匹配的平台配置，避免混用互相冲突的旧式缩放接口。
- 自定义输入行为按状态机实现，包含开始、更新、完成、取消与捕获丢失。结束路径可重复调用，完整恢复光标、捕获和临时状态。
- 清楚定义窗口所属关系、焦点、激活和模态行为，弹出内容不能阻断后续正常输入。
- 初始焦点符合页面主要操作；编辑型界面保留直接输入能力，浏览型界面可聚焦非编辑区域。资源优化不能通过破坏输入法、键盘操作或辅助技术支持实现。
- 平台窗口定位、托盘和装饰能力按实际窗口系统验证；受限能力提供适合的回退，不假设不同操作系统及 Linux 桌面环境行为完全相同。

以下能力仅在产品需要时实现，并单独验证：

| 可选能力 | 平台验收重点 |
| --- | --- |
| 无边框、透明或特殊形状窗口 | 首帧、阴影、缩放、命中测试、辅助功能及渲染成本 |
| 托盘与自定义菜单 | 焦点、外部点击关闭、键盘操作、系统层级及托盘重建 |
| 置顶及特殊窗口层级 | 事件驱动诊断与恢复、正常焦点、与其他系统界面的协作 |
| 自定义拖动、缩放或吸附 | 捕获丢失、取消、多屏、混合 DPI 和窗口尺寸稳定性 |
| 原生资源卸载及重建 | 句柄失效处理、事件重新绑定、原生属性和输入恢复 |

平台原生控件与菜单的视觉定制范围需要在设计阶段确认。需要完全自定义时，将交互、焦点、无障碍和系统兼容成本一起纳入实现范围。

### 6.1 窗口外框、圆角与阴影

优先由系统窗口管理器提供顶层窗口的边框、圆角和阴影，使其与激活状态、最大化、贴靠和系统主题一致。系统装饰与应用自绘装饰明确分工，同一层级只保留一套外框和阴影。

保留原生标题栏是默认起点，窗口标题应准确显示应用或当前内容身份；标题变化同步到系统任务切换等入口。若标题栏、页签已经表达相同信息，内容区不再重复增加品牌或占位标题行。需要自定义标题栏时再按第 6.2 节实现，不因内容区采用圆角卡片或主题配色而移除系统装饰。

| 项目 | 参考表现 |
| --- | --- |
| 外边框 | 系统细描边优先；自绘可从 1 逻辑像素起步，颜色与背景协调，避免粗矩形外框 |
| 圆角 | 原生窗口采用系统支持的外观；自定义面板可从约 8～12 起步，不强制各平台使用同一半径 |
| 阴影 | 柔和、低不透明度，边缘连续，无黑角、重影和明显裁断 |
| 激活状态 | 活动与非活动窗口有适度区分，正文与控件保持可辨识 |
| 最大化 / 全屏 | 随系统规则调整圆角、边框和阴影；外部装饰留白不应侵占可用内容区 |
| 首帧与恢复 | 首次显示、还原及重建窗口后装饰完整，无默认粗边框闪现或尺寸跳变 |

- 系统已提供阴影时，避免再给整个根控件附加 QGraphicsDropShadowEffect、模糊图层或额外阴影窗口。大面积透明缓冲与模糊效果先测量内存和重绘成本。
- 必须自绘阴影时，为内容边界之外的绘制保留足够空间；区分内容区、阴影区和缩放命中区，避免透明装饰阻挡下层点击，同时保持所需的边缘缩放能力。
- 自绘阴影可从约 8～20 的模糊范围、2～6 的向下偏移和 8%～16% 的黑色不透明度开始试稿。不同 Qt 效果 API 的半径与偏移单位按其定义换算，不能将同名参数直接视为相同视觉效果。
- 自绘细线按实际 DPR 对齐到合理的像素边界；分数缩放下核对线宽和抗锯齿。圆角处背景、边框和子内容裁剪一致，不能用透明黑底或厚描边掩盖接缝。
- Windows 可在原生句柄可用时评估 DWM 的圆角、边框和非客户区能力。检查 API 支持范围及返回结果，句柄重建后按需重新应用；不支持某项外观时使用稳定的系统回退。
- 无边框定制需保留或补齐系统缩放框架、非客户区与命中测试；不能假定移除标题栏后系统阴影和圆角仍自动保留。设置窗口 mask、透明属性或原生样式前，验证其对系统合成的影响。
- macOS 等平台遵循各自的窗口装饰及标题栏机制；不通过统一自绘强行复制另一平台的边框和阴影。深色主题、高对比度与远程桌面环境按声明支持范围验证。
- 验收覆盖活动与非活动、拖动、缩放、最小化恢复、最大化、贴靠、全屏及混合 DPI。检查任务栏未被遮挡、阴影不重复、透明角无黑块、外部装饰不截获无关输入。

### 6.2 自定义标题栏与窗口控制按钮

需要自定义标题栏时，外观与应用主题统一，窗口操作保持平台习惯。以下尺寸为常规桌面密度下的参考值，触控、较大字体及平台原生按钮可采用不同尺寸。

| 项目 | 参考值或表现 |
| --- | --- |
| 标题栏高度 | 约 36～48，文字与控制按钮垂直居中 |
| 标题文字 | 清晰简短，长标题合理省略，不挤占窗口控制区 |
| 控制按钮 | 点击区域可从宽 40～48、接近标题栏高度起步；视觉图标可更小 |
| 图标 | 约 14～18，使用一致的线宽和光学对齐，高 DPI 下清晰 |
| 状态 | 覆盖悬停、按下、焦点和非活动状态；关闭按钮可采用符合平台习惯的危险色反馈 |

- 拖动区域与按钮、输入框、菜单等交互区域明确分开。标题、图标等装饰内容不应意外阻断拖动，也不能让拖动命中吞掉按钮点击。
- 优先评估 QWindow 的 startSystemMove()、startSystemResize() 或平台对应能力，保留系统拖动与缩放体验；自定义实现补齐取消、捕获丢失和多屏处理。
- 支持适用的双击最大化或还原、最小化和关闭行为；最大化状态及时更新图标、工具提示与无障碍名称，关闭不需要的边缘缩放命中。
- 系统菜单、快捷键和贴靠能力按目标系统验证。Windows 的最大化按钮悬停布局等行为需单独处理与验收，不能认为普通自绘按钮自动具备全部原生标题栏能力。
- 控制按钮提供明确的无障碍名称与工具提示。边缘缩放区与按钮点击区冲突时，按位置和窗口状态明确优先级。
- 最大化按当前显示器工作区放置，还原后保留合理的位置与尺寸；跨屏及 DPI 变化时同步校准命中区域。
- 验收覆盖双击、按钮、键盘、八方向缩放、快速拖动和跨屏，检查操作区域稳定、图标状态正确、焦点反馈可见。

### 6.3 输入路由与聚焦控件

- 破坏性列表快捷键只归属具有真实焦点的目标视图，行内编辑／输入框／其他内容控件保留按键原义；忽略自动重复造成的重复确认。确认前复制稳定 ID／路径值，返回后重新核对目标会话和有效状态，不能持有可能被异步刷新销毁的行指针。
- 快捷键按应用级、窗口级、组级与控件级明确作用域，业务动作作用于当前有效目标。文本编辑、表单选择、菜单与专用内容控件可能赋予同一按键不同含义，优先保留标准控件与平台的输入约定。
- 普通表单的 Tab／Shift+Tab 继续焦点遍历；查找关闭后回到来源内容。仅在已声明需要接收原始 Tab 的专用控件获得焦点时局部接管，避免全局事件过滤吞掉其他表单导航或既有全局快捷键。
- Qt 的事件处理可能在 keyPressEvent 之前完成 Tab 导航或快捷键处理。定位问题先核对事件路由、焦点代理与 ShortcutOverride 等机制，只拦截确有归属的事件；不要将所有没有 text 的按键一概丢弃而破坏方向键等输入。
- 纯 Control／Shift／Alt／Meta 等修饰键不应在业务文本输入尚未发生时清除选择或提交数据；组合键回归包含修饰键按下、字符键按下／释放、修饰键释放的物理序列，并区分自动重复。平台 Qt 键值／修饰符映射与常用标准快捷键分别核对，不能只在测试中附一个 modifier 标志就认定真实按键正确。
- 选择是否存在以 selection model 或有效范围判断，不以 trim 后字符串是否为空判断。空格、缩进、反向范围、宽字符与组合文字的复制保真；单击定位、拖选和查找选区的起止策略明确。清除高亮及时重绘，不能通过重建内容来刷新选择。
- 调整编辑器行距时，文本、行号、光标、命中、翻页与滚动应使用一致的布局几何，并保留中文回退字体等自然字形高度。字号和界面倍率从基准计算，不反复叠加留白；不能插入空行或格式命令污染内容和撤销栈。大文档继续按可见范围惰性布局，明确对象所有权和缓存边界。
- 输入法、键盘焦点、标准 Copy／Paste 与无障碍语义随控件迁移仍有效。自绘光标或内容视图需更新输入法查询矩形；主题或布局变化不重置正在输入的内容。

#### 按需特例：终端或协议输入视图

以下仅适用于产品确有终端／协议输入能力时，不应用到普通编辑器、表单或下拉框。

- 焦点位于终端时，Tab／Shift+Tab 按所支持协议发送，可连续或自动重复，不转移到其他控件；例如 VT 兼容协议常见普通 Tab 为 0x09、反向 Tab 为 ESC[Z，具体编码由协议库和模式决定。补全交给实际命令环境，不在客户端伪造目录候选、提示符或会话重启。
- 如果采用“有选区 Ctrl+C 复制、无选区发送中断”的交互，则有效鼠标／查找选区（包括全空白）复制后清除高亮并消费事件；下一次独立 Ctrl+C 无选区才发送一次中断输入。防止同一次按住按键的自动重复在复制后变成误中断；可消费此组合的重复，但不能把规则扩散到所有字符或 Tab。
- 终端专用纯复制快捷键、平台标准 Copy 与明确的“中断”菜单分别定义。菜单应说明是直接中断还是按选区语义处理，复制保持合理的浏览位置，中断后是否回到最新输出由产品明确。中断字节发出不等于命令已结束，后端响应由实际运行环境决定。
- 自绘终端光标位置、显隐、闪烁和形状按协议状态绘制；仅位置或显隐变化也触发旧／新区域更新，宽字符内的光标与文字保持可读。移动和输入等待协议反馈，不在本地伪造输入缓冲。
- 闪烁遵循系统偏好与协议允许的状态；系统关闭闪烁时常亮，后端隐藏时不能强行显现。只在可见、聚焦、活动且正在显示当前内容等必要条件下启用视觉计时器，失焦、隐藏或回看历史时停止；恢复条件后从清晰状态显示，无全局轮询。
- 验收真实按键序列、精确字节／事件次数、焦点保持和其他普通控件不受影响。协议 echo fixture 只证明字节路由，不可宣称已验证真实命令环境的补全、中断或任务恢复。

## 7. 数据、配置与诊断

- 文件、网络和其他外部输入具有大小、超时、取消及错误处理边界。仅对可安全重复的操作实施有上限的重试。
- 配置存放在平台标准用户目录，带版本与迁移策略，采用适合的安全写入方式；升级保留用户数据。
- 应用及组织标识在首次发布前确定，显示名称变化时明确数据目录兼容策略。可写路径可使用 QStandardPaths，随包只读资源可使用 Qt 资源系统或明确的部署路径，不依赖启动时的工作目录。
- 整体替换文件时可采用 QSaveFile 等安全保存方式，检查写入与提交结果。配置迁移或读取失败时保留可恢复来源，明确错误反馈；不能静默覆盖损坏文件。数据库按其事务及迁移机制处理。
- 需要持久化的敏感信息使用平台提供的保护机制，日志不包含凭据和无关隐私数据。
- 持久时间点明确时区，短时耗时和动画计算使用合适的单调时钟。
- 诊断日志记录必要的版本、事件、原因、耗时及资源状态，设定容量上限。性能问题能够定位到具体场景和构建版本。

## 8. 性能与质量验收

### 8.1 内存测量

在 Windows 上同时区分以下指标；其他平台选择等价工具，并注明口径：

| 指标 | 用途 |
| --- | --- |
| 私有工作集 Private Working Set | 当前驻留 RAM 且由该进程独占的页，接近常见任务管理器默认内存口径 |
| 私有提交 Private Bytes | 进程私有已提交内存，用于观察持续增长和分配开销 |
| 总工作集 Working Set | 当前驻留 RAM 的全部进程页，包含可共享页面 |
| 图形资源、句柄、线程、CPU 和 GPU 指标 | 检查资源增长、后台工作和渲染成本 |

以上指标不相加、不互相替代。多进程应用同时报告整个应用及必要的进程明细，GPU 资源与缓存按工具能力单独说明。

- 使用无调试器的 Release 构建，记录程序版本、Qt、系统、硬件、DPI、数据规模及测量工具。
- 覆盖首次打开、核心内容加载、重负载、主要页面访问后空闲、反复操作及持续运行等代表性场景。
- 每场景稳定后多点采样，前后比较使用相同条件并进行多轮复测，记录稳定值与峰值。
- 对重复操作同时观察提交量、对象、句柄和纹理是否持续增长。缓存预热后的平台期与无法解释的持续增长分别处理。
- 优化结果附带视觉、动画和交互回归，确认资源收益与产品表现同时达到要求。

对疑似资源保留，先建立可重复的开关／迁移场景，再判断是否需要修改所有权：

1. 在隔离进程、临时配置和受控数据中预热，再重复打开、使用、关闭；覆盖实际关闭入口、保存确认、浮窗收回和事件循环的延后删除。样本规模与风险相称，不为测量而撑爆进程，也不改用户配置或运行窗口。
2. 同时采集业务对象、文档／模型、辅助控件、原生资源和句柄等数量，用 QPointer 或销毁信号确认预期对象回收。关闭时只隐藏的对象、缓存和长期服务分别记录，不能只看某个文档指针销毁就认定整棵界面无保留。
3. 记录 warm、open、close 等阶段的原始采样与时间，区分初次字体／样式／对话框／算法预热、分配器保留、合理缓存平台期与按轮增长。Working Set 未立即下降不等于泄漏；对象销毁也不保证分配器立即把所有提交页还给系统。
4. 修改前保留基线程序或可复现构建及源码哈希；修改后用同参数、相同 probe 和可比条件测量，不把不同 UI／数据规模的运行直接比较。多进程测量明确并发干扰和采样口径；复测次数与结论强度相符。
5. 若只剩少量未解释对象，做定向重复诊断，记录 class、objectName、parent 与是否同一对象／按次增长。未定位来源就保留未知边界，不武断称为缓存；不要为掩盖它而强制清空工作集或盲删 Qt 内部对象。
6. 报告明确已证实的对象保留根因、修复后生命周期结果、内存范围与未覆盖场景。单次有限场景的前后变化不能推出整个应用零泄漏；局部算法耗时下降不能宣传为全局性能倍数，多项优化合测也不能凭差额拆出单项贡献。

### 8.2 视觉与动画验收

- 核对所有适用交互状态、长文本、字体回退、空内容、加载、错误及溢出表现。
- 覆盖目标缩放比例；Windows 项目通常包含 100%、125%、150%、175%、200%，多屏需求增加真实混合 DPI 验证。
- 在最低目标硬件及声明支持的刷新率下检查动画，覆盖连续触发、反向、打断、隐藏后恢复和减少动画模式。
- 测量启动、首次可交互、页面切换、动画帧耗时与空闲 CPU，确认界面无闪烁、输入阻塞和明显慢帧。
- 自动化事件与强制缩放用于补充回归；真实输入、窗口合成及多屏效果在对应设备验证。
- 对卡片、按钮、表单、徽标、提示条和弹窗分别核对圆角裁剪、图文对齐、焦点与禁用状态；状态变化不能引起非预期的尺寸跳动。
- 对窗口外框和标题栏覆盖活动与非活动、最小化恢复、最大化、贴靠、全屏和平台外观回退，检查阴影、边框、透明角与命中区域。
- 主题适配按声明支持范围覆盖浅色、深色和高对比度。正常字号正文可将 4.5:1 作为文字对比度验收基线；大号文字与关键非文本控件边界可将 3:1 作为基线，按采用的无障碍标准确认字号分类和例外。

对项目实际采用的组件，增加与风险相称的行为检查；不为每个颜色值编写镜像样式断言：

| 能力 | 重点检查 |
| --- | --- |
| 动态表格／列表 | 连续快照重排、业务 ID 保选、删除不串选、空样本、排序与双向滚动／列宽／焦点保留、失焦选中可读 |
| 页签与动态分组 | 小窗口长页签、按钮与滚动区不重叠、所属组动作、批量关闭保存保护、方向连续、拖影／预览／取消与来源失效 |
| 下拉框 | 当前项靠后、上下弹出、屏幕边缘、不遮自身、Esc 重开一致、键盘／鼠标提交次数和父窗口移动 |
| 路径与查找 | 路径显式提交和取消／失败、导航历史；查找固定在内容容器、正文滚动独立、Esc 回焦点与多视图归属 |
| 窗口与生命周期 | 隐藏／最小化／关闭／退出区别、浮窗收回、任务继续或取消的明确策略、重复打开关闭的对象与资源数量 |
| 输入特例 | 标准表单导航与专用控件原始按键各自正确，物理修饰键序列、选择语义、自动重复与输入法 |

离屏截图使用真实生产控件、目标字体与代表性数据，缺字方框、只绘制设计示意或参数检查不能替代实际外观证据。offscreen、事件模拟、本地 fixture、真实平台窗口与真实业务环境分别注明覆盖范围；验证前者不代表后者已经通过。确认已有检查覆盖且结果有效后，只有新变化、失败或未解决风险才增加测试。

业务算法、数据处理和资源生命周期按风险安排单元或集成测试；视觉和动画需结合真实渲染验证。测试规模与变更相称，验证结论注明范围。

### 8.3 交付时需要保留的验证结果

| 类别 | 可复核的结果 |
| --- | --- |
| 工程与构建 | 依赖及工具链版本、配置与构建命令、产物位置；从干净检出能够按说明复现 |
| 部署与平台 | 声明支持的平台和架构对应的构建、打包及启动结果，记录实际验证环境 |
| 界面与交互 | 主要界面及关键状态的真实渲染结果，目标 DPI、主题、键盘、输入法与窗口交互结论 |
| 性能与资源 | 代表性场景、原始采样或可复测记录，与项目预算的比较结果 |
| 稳定性与数据 | 适用的反复操作、关闭与取消、保存失败及升级迁移验证结果 |

实际使用的可选能力纳入相应验收，不适用项注明范围。未验证、未通过和已通过分别记录；源码可编译、安装包可生成及目标设备可正常运行是不同结论。影响使用的未通过项修复后再完成相应交付。

## 9. 构建、部署与维护

- 构建、检查、依赖部署、打包及校验统一为可重复脚本；区分开发、测试和发布配置。
- 保持编译器、运行库、架构及 Qt 库 ABI 一致，按实际模块部署插件和运行时依赖。
- 包含实际使用的平台插件、图像格式插件、数据库驱动、TLS 后端及 QML 模块等运行依赖；以打包后的行为验证完整性，不以开发机能启动代替部署验收。
- 在没有 Qt SDK 和开发机环境变量的干净系统验证安装、启动及所用平台能力；检查升级、卸载和配置保留。
- 统一程序、资源和安装包版本，保留构建标识、校验值及必要的回退产物；按发布要求进行代码签名。
- 记录 Qt 模块、插件及第三方组件的许可证与部署义务。依赖升级后复测内存、字体、动画及平台行为。
- 本地构建与正式发布使用独立入口，更新遵循项目明确的发布流程。
- 将适合自动化的配置、构建、测试和打包检查纳入持续集成；涉及系统合成、真实输入和目标硬件的验收单独保留环境与结果。

## 新项目可直接使用的开发要求

> 优先使用 Qt 6 + C++ + CMake 开发桌面应用，将内存效率、视觉表现和动画体验作为并列的高优先级目标，正确性与稳定性作为交付前提。先明确支持平台、工具链、视觉主题、资源预算和验收条件，再用代表性原型验证所选界面技术的关键风险。界面采用统一的视觉规范，覆盖主题、完整交互状态、高 DPI 与首帧表现；组件按需求采用，参考尺寸与色值适配项目主题及无障碍要求。保留可辨分区与紧凑操作，减少重复标题和无需求控件；动态数据按稳定业务 ID 保持用户状态。顶层窗口优先使用系统标题栏、边框、圆角和阴影，自定义标题栏保留平台窗口操作。动画具有一致的时长与缓动，支持平滑打断和反向，保持输入响应。页面和服务合理复用，按需创建及释放资源，缓存有边界，隐藏界面停止无用视觉工作但不隐式取消任务。明确 QObject 所有权、控件替换、异步生命周期和线程归属，区分最小化、隐藏、关闭、收回与退出。输入按聚焦控件和平台语义处理，专用控件不破坏普通表单导航。资源路径和数据保存适配平台，升级保留用户数据。编辑器、分屏、查找、终端、浮窗和平台特殊能力均按需求启用。使用 Release 在目标硬件上测量内存、对象数量、CPU、启动响应及动画帧耗时，优化同时验证视觉与交互质量，不以瞬时内存数字代替生命周期证据。提供可重复构建、部署和打包流程，完成干净环境验证，并保留各项验证结果及适用边界。

### 提示排版与紧凑原生表头的验证契约

提示正文的测量与实际文本布局应使用同一字号、换行和行距，覆盖中文、显式换行和长路径；不能只扩大测量高度。保留原生标签及可复制语义，避免为排版破坏原生对话框内部布局所有权。标准操作按钮在常态和禁用态也应有可辨识的单层边框；限定在提示组件，不扩散到工具栏。运行时首次设置QSS属性后必要时立即repolish，首显像素验收应早于主题切换。

紧凑原生表头须联合定义字体、padding与最小高度，实际label子区域应容纳字体及排序箭头。对特定表格限定样式，避免全局padding挤掉中文上下笔画；尺寸随缩放变化，窄表格使用横向滚动而不是垂直裁字。


### 有状态协议的等待与重连

本地等待阈值与底层断线必须分开：阈值只报告响应缓慢。异步协议返回EAGAIN时保留原API、参数、缓冲地址和长度，完成前不重放文件变更或输入；等待期间仍处理交互通道与显式停止。真实peer关闭、操作系统传输错误和用户停止另行结束连接。只读后台采集可使用独立、有限时且有退避的工作连接，失败不得连带关闭交互会话。空闲worker由提交/停止事件及下一次keepalive期限唤醒，不引入高频空轮询。

重连保留视图、历史与布局，只重新创建因断线中断的远端通道；正常退出与用户关闭的通道不擅自复活。旧worker回调校验来源及连接代次，同时释放其输出配额。目录只承诺恢复已确认的信息，启动目录不冒充实时cwd；失败回退须明确告知。

连接诊断仅记录固定阶段枚举、模式、错误码、耗时/阈值及主动/异常退出；只在关键建连、慢等待/恢复、异常和退出时产生记录，沿用有界队列/轮转，不按键或每轮poll落盘。不得记录错误原文、命令、凭据、地址、用户名或文件内容。

### 树列表的视觉和交互契约

树列表的整行背景、层级引导线和展开标记应随主题及缩放协调变化；多个列共享行选择和拖放目标，层级缩进、空白区域、长文本、操作按钮与编辑器各有明确命中规则。导航项、占位项和不可用项不得触发普通业务动作。同组平级条目如需连线，可以使用稳定业务身份和首／中／末位置描述，不应为了装饰引入虚假业务父项。

展开、悬停动画可被中途反向；模型修改、排序、过滤、折叠、隐藏、缩放和销毁时清理失效的瞬态状态。采用公共视图 API 保留键盘、焦点、选择和无障碍语义；缓存有上限，空闲时不持续驱动动画。批量修改期间如屏蔽视图信号，调用方仍须显式处理瞬态状态及无障碍缓存。视觉覆盖层、框选、拖放预览和嵌入编辑控件分别检查绘制顺序和命中，离屏事件与真实系统输入的证据范围应分别标注。
