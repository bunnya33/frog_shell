# RabbitShell 交互设计检查清单

## 0.1.32 目录自身拖动

- 可信同服务器内部拖动落到任一选中来源目录自身时，整批无操作：正常 Move 响应，无预览、底部提示或 tooltip，释放不确认、不建任务/历史、不写远端。混选其他项目也不能意外移入该目录。
- 原父目录 no-op 和混选跳过已在目标目录的项目保留；严格后代、非规范路径、失效来源及跨服务器仍拒绝。粘贴自身限制和移动后端不变。以下历史版本的“自身拒绝”描述由本节更新。

## 0.1.30 资源菜单、重名与按钮反馈

- 无法粘贴时从资源右键隐藏粘贴，有效本地文件/目录或可信剪切记录时显示；打开期间实时更新，实际操作继续复用只读前置判断和原捕获目标。
- 资源导航栏最右侧“更多”提供显示隐藏文件、显示修改时间列；右键移除这两项。弹出时同步 checked，保留原偏好、列宽、过滤、键盘和可访问语义。
- 冲突标题按复制/移动/上传区分，默认及 Esc 均为通用“取消”。保留两者编号放在扩展名前，常见 tar 复合后缀保留；目录点号不当扩展、`.env` 不拆分。目标锁覆盖编号后的真实路径，取消和候选已占用时不覆盖原目标。
- 内部落到原父目录接受 Move 手势但无任务、确认、历史或远端写入，清除预览及底部提示；混选跳过 no-op 项。自身/后代、失效 token、跨服务器和原移动保护保留。
- 全应用标准按钮 hover/pressed 可辨，checked 标记与焦点不被遮盖、禁用不响应，释放恢复 hover 且不移动布局。私有/offscreen 与 loopback 验证、实际两主题截图见 [0.1.30 验证记录](RabbitShell-0.1.30验证记录.md)。以下版本节保留当时规则。

## 0.1.29 拖动、粘贴与字体交互

- 有效内部来源从源行、同目录空白、链接或草稿等无效入口拖入时先建立 Qt 路由，当前位置仍不可放下；移动至合法父级、子级、展开的深层或其他目录后才显示 Move 与正确目录高亮。`..` 只作为内部移动的父目录目标，不成为来源、本地上传或剪贴板粘贴目标。身份、代次、确认、同目录无操作、自身/后代保护及原撤销保留。
- 菜单粘贴仅对合格本地文件/目录或有效同服务器剪切启用；文本、网页、伪造/失效令牌、跨服务器剪切及尚未准备完成的复制置灰，菜单打开期间随剪贴板/连接状态更新，实际粘贴复用同一前置检查。
- 设置字号/缩放等控件需点击启用且拥有焦点后才滚轮改值；未启用时滚动父页面，点击外部退出，键盘与下拉 popup 原操作保留。
- 编辑器使用参考比例 14px 字号→约19px 行高，随字体像素和 UI zoom 调整、保留更高自然字形，不是固定 +2/+4；行号、命中、滚动与文本撤销保持。证据及边界见 [0.1.29 验证记录](RabbitShell-0.1.29验证记录.md)。

## 0.1.28 资源菜单与本机诊断

- 仅资源树四种上下文菜单采用紧凑矢量图标；最小 248px 宽、29px 行高、18px 图标、13px normal 正文，1px 外框内保留 4px padding，hover 内圆角 2px，按 UI 缩放/DPR 绘制。超高菜单保持原生单列上下滚动，鼠标箭头和键盘均能到达全部动作。
- 隐藏文件与修改时间的图标固定在左、勾选固定在右，真实 QAction checked、键盘、鼠标、无障碍和回调目标保留；快捷键显示在右列。
- 移除单文件“打开文件”菜单项，保留原 itemDoubleClicked 双击打开；资源树不新增 Enter 激活，没有空组或多余分隔线。inline 新建 Return 不得额外打开其他行。
- 行菜单先下载/上传，再新建，再剪切/复制/粘贴/重命名；删除独立组、单项属性置底。空白菜单先新建/上传，再粘贴/撤销，条件收藏组之后是视图动作，不显示禁用剪切/复制。回调仍捕获原目标。
- Windows 增加本机有界异常记录及 portable 非零 ChildExit 记录；不含正文、凭据或 dump，不增加服务器调用。此前闪退根因未知，异常码/模块偏移均为最佳努力，退出码 73 不判定为崩溃。规则及验证边界见 [诊断说明](RabbitShell-0.1.28诊断说明.md) 和 [验证记录](RabbitShell-0.1.28验证记录.md)。

## 0.1.27 资源导航与文件操作

- 非根目录的 `..` 只导航，始终置顶且不参与文件操作；目录在文件之前，目录大小排序按名称，文件按真实大小。
- 资源树支持剪切、复制、粘贴及同服务器内部拖动；远端复制完整准备后才可本地粘贴，剪切仅同服务器移动。拖动默认确认，文件拖出本地保留原有 Windows 复制方式。
- 资源树 Ctrl+Z 仅撤销当前会话中符合条件的新建、重命名和移动；删除及覆盖阻断整批撤销，非空新上传目录不能自动撤销。不会在远端创建恢复文件或覆盖备份。
- 主动保存或上传使用短期 `.part`；正常成功及取消清理，异常退出或断线可能残留。服务器变更互斥，繁忙时无关路径也可能需稍后重试，草稿保留。验证范围见 [0.1.27 验证记录](RabbitShell-0.1.27验证记录.md)。

## 0.1.26 终端清屏与切屏

- 主屏清屏保留光标所属完整可见软行、cells/样式及原 row/column，清其他主屏行、历史和选区；上方留空白，不把输入挪到顶部。零 PTY 字节，不发 Ctrl+C/Ctrl+L/Enter，不伪造提示符、不重建终端。
- 备用屏禁用并提示保护 TUI/主屏；软行前缀已跨入历史时禁用并说明原因。没有 shell integration，不宣称识别硬换行多行语法单元或任意超长命令。菜单激活时再次核验模式。
- 保留 .16 reflow/宽字/组合字符/pending-wrap 补丁。1047/1049+历史、resize、失焦与重绘对照通过；不自动删除光标下方内容。用户实际 Vim 覆盖现象尚未完整复现，不声称已根治。
- 切屏/实际 grid resize/成功清屏仅补有界数值状态诊断，不记录命令或正文。见 [终端清屏与切屏](RabbitShell-终端清屏与切屏.md) 和 [0.1.26 验证记录](RabbitShell-0.1.26验证记录.md)。下列版本节保留历史规则。

## 0.1.23 文件树辅助功能缓存

- render屏蔽树信号时仍显式清理，filter在setHidden前清理；析构先断开derived回调。保留Windows辅助功能，不把关闭UIA或输入法当修复。
- 缓存层次变化后的MD真实单击、双击/合成read、编辑器创建关闭已验证；已修复确定的缓存循环缺陷，用户现场数GB增长全过程仍未证实复现。证据与范围见 [0.1.23 验证记录](RabbitShell-0.1.23验证记录.md)。

## 0.1.20 上传目标、实际冲突和目录刷新

- 本地真实 URL 仅 Copy；目录整行（含大小列、缩进区域）落入该目录，普通文件行落入父目录，空白落入已提交浏览根。链接/草稿/未知目标明确拒绝，不空路径回退到根。预览为整行边框与「上传到 /完整路径」，离开、投放、隐藏、目标删除/变化清理，保留选中和框选。
- 右键上传在菜单打开时捕获路径，文件选择期间的导航/选择不改目标，队列 Job 明确保存目标。Qt itemAt 通常支持任意列，不将第二列误写为根因。
- 上传默认 ask；真实 SFTP 同名才异步显示「取消上传」「替换文件」「保留两者」，无下拉/跳过按钮。保留两者自动序号重命名；类型不同或链接禁用替换，默认和 Esc 取消；可勾选应用到同批次后续冲突。下载旧策略不改。
- 同名等待以 Session/job/nonce 和当前 dialog 身份保护，取消/退出唤醒且不计有效时间。仅 NO_SUCH_FILE 是不存在；提交先用不覆盖 rename，期间新同名再次询问，有界失败清临时文件且不主动删除旧目标。
- 刷新同一代次按父结果继续列出展开可见子目录，不重建树；收起/隐藏已加载枝标未加载，下次展开重新获取。保留展开、选择、焦点、滚动、未提交草稿；旧导航/消失父项/类型变化响应拒绝。上传结果局部更新受影响的已加载父目录，大小 tooltip 包含精确 bytes。
- 实际证据与限制：[0.1.20 验证记录](RabbitShell-0.1.20验证记录.md)。

## 0.1.19 系统文件拖出与页签反馈

- Windows普通文件最多256项多选拖出，文件图标拖影；目录/链接/新建占位与混合选择拒拖。Ctrl/Shift/空白框选/整行点击、本地文件上传保留。非Windows保留下载菜单，不宣称系统拖出可用。
- 格式枚举、元数据、hover和Stat不取远端内容；释放且目标读取IStream才进入既有SFTP队列，64KiB磁盘流。源文件尺寸/时间改变明确失败。最终落点/重名交给系统目标，不写下载路径偏好；暂存完成与系统接收分开，已结束拖出不重试失效暂存。
- FileView拖出信号以QueuedConnection接Workspace，先退出Qt itemview startDrag事件栈；原生循环允许关闭源，回程不访问销毁的source/owner。异步目标持有最后stream前保留spool；取消/断开/源关闭停止自有任务并释放。
- 编辑页签小拖影含原文件图标，应用窗外Ignore cursor显示小窗口和向外箭头，RabbitShell窗口内无效区禁止，合法内部目标Move。DragReleaseGuard继续区分明确释放、Esc和原生取消；跨服务器无效目标仍禁止，源销毁不浮窗。
- 证据/限制见[0.1.19验证](RabbitShell-0.1.19验证记录.md)，不以离屏COM测试冒充真实Explorer或混合DPI桌面验收。

## 产品原则（2026-11-04 用户确认）

- **远端零安装。** 直接使用服务器已有的 SSH 服务及其开放的终端、文件传输、端口转发等能力；不要求安装额外工具、运行时、Agent 或 VSCode Server，也不部署 RabbitShell 辅助程序。这是后续设计与开发约束，不代表当前所有场景已经通过验证。
- 服务器状态、进程、端口归属等附加信息，仅在现有系统接口／工具和当前账号权限能直接取得时展示。取不到就省略相应附加内容，不为补齐信息要求安装、提权，不用虚假的零值、过期数据或占位说明填充界面。
- 附加信息缺失不得阻止 SSH 连接、终端或允许的隧道转发。各项核心能力仍受服务器开放情况限制：例如文件传输需要可用的 SFTP 子系统，转发需要服务端许可；真实操作失败应明确反馈，不能按“附加信息省略”隐藏。
- VSCode 仅作为交互参考，不以复刻其远端组件和全部信息字段为目标。采集按需进行、有超时与资源上限；能力不可用时停止无效探测。
- 隧道目前处于方案阶段，细则见 [SSH 隧道实现方案](RabbitShell-SSH隧道实现方案.md)。本节优先于历史方案中可选采集 Agent 或必须显示“不可用”占位的建议。

## 统一窗口规则（2026-11-03）

- 同一连接配置默认对应一个服务器工作区；重复连接切回已有页签，已断开时在原工作区重连。切换目录不会生成新工作区。不同账号、不同连接配置仍可分别打开。
- 切换连接管理／服务器页签保留各自的目录、草稿、编辑分组、终端、浮窗和传输；不会销毁重建工作区或结束终端进程。
- 顶层页签显示环境、服务器名称、连接状态和未保存标记；标题栏显示当前服务器、账号与地址。详细延迟仍位于工作区左下角。
- 文件浮窗标题显示环境和服务器，路径栏显示完整远端路径，提供返回所属工作区并收回文件；切换服务器时所属浮窗随工作区隐藏，切回恢复。
- 断开连接保留草稿与历史输出，运行中的传输转为等待连接；终端会话结束，重连建立新会话，不声称恢复原进程。
- 关闭服务器页签汇总该服务器的未保存文件、终端、前台任务、未完成传输和浮窗；取消／保存并关闭／不保存并关闭。保存失败或冲突时不关闭工作区，交给已有保存保护处理后重试。
- 退出主窗口汇总全部服务器；确认退出时结束会话、取消未完成任务，并关闭所属浮窗。关闭与最小化分开：原型提供退出流程演示，系统最小化、托盘和真正跨屏窗口尚未实现。
- 固定连接管理页签不提供关闭按钮，随时可回到连接管理；“＋”也返回连接选择。移走整个服务器工作区到独立系统窗口作为后置增强，首版不提供复制连接式“新窗口”。

## 建议首版补齐：尚未全部画入原型

| 优先级 | 缺失项 | 建议的默认规则与原因 |
| --- | --- | --- |
| 必需 | 连接管理 | 保存主机、端口、用户名和认证方式；连接与断开入口；主机指纹首次确认及变化提示；失败原因可读。避免只有“已连接界面”而缺少进入和退出流程。 |
| 必需 | 搜索、排序与隐藏文件 | 当前目录按名称过滤，名称／大小／修改时间排序；显示隐藏文件开关。`.env`、`.ssh` 等常见文件必须可以找到。 |
| 必需 | 权限细节 | 链接目标、ACL 和特殊权限位进一步设计；递归改权限要区分目录与普通文件，避免给普通文件统一增加执行权限；不默认提权或修改所有者。 |
| 必需 | 编码与草稿恢复 | 增加编码、换行类型切换；非 UTF-8 文件识别及转换提示；应用意外退出后的本地草稿恢复。本轮草稿仅在当前原型窗口内保留。 |
| 必需 | 传输后续边界 | 真正的系统保存位置选择、磁盘空间不足、部分成功及取消后的临时文件清理；断点续传依赖实现能力，不以“继续”或“重试”文案承诺真实支持。 |
| 必需 | 断线与退出 | 分别说明终端、未保存文件、传输任务的状态；退出应用时汇总未保存内容和未完成任务，允许取消退出。普通 SSH 重连不能承诺恢复原进程。 |
| 必需 | 焦点与窗口规则 | 明确当前编辑组和终端；浮窗关闭、收回、最小化、应用退出分别定义；真正跨屏窗口需要与主窗口统一保存及连接状态。 |
| 建议 | 多服务器身份 | 每个工作区、文件组和终端明确标注所属主机；生产／测试环境可标记，避免在错误服务器上修改或终止进程。 |

## 后续逐项设计时应检查的闭环

每项功能同时覆盖：入口、进行中、成功、失败、取消、重试、断线、权限不足、未保存内容，以及与其他窗口或任务的相互影响。

不要把“分屏”“隐藏”“移到浮窗”混同于“关闭文件”或“终止进程”；不要把“页面已保存”的模拟状态当作真实远端写入成功。后续改动以这份清单持续核对，不依赖用户逐一发现缺项。
