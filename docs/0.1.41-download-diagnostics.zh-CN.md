# 0.1.41 目录双击与下载来源诊断

用户报告双击资源目录后出现“下载 · N 项”，没有看到下载位置选择窗口。目前未复现，不能把新增诊断称为已修复根因。普通目录、嵌套目录与上级目录的双击路径仅导航；普通下载任务组来自资源菜单明确选择下载、随后完成本地目录及同名策略确认的路径。

增加隔离 UI 回归，分别双击目录名称列、大小列、嵌套目录及上级目录，验证只有 list 请求、没有下载任务或系统拖出。菜单 Escape/关闭必须不触发下载。测试仅临时配置、offscreen 和不启动的 fake Session，不接真实服务器、不触碰系统剪贴板。

当用户在设置中明确开启日志时，新增 `FileActivate`、`DownloadRequested`、`DownloadQueued`、`TransferStart` 事件。`origin` 仅记录固定类别：`resource-double-click`、`resource-menu`、`clipboard-preparation`、`system-drag`、`existing-queue`。这些事件不记录原始路径、文件名、文件内容或剪贴板内容；默认日志关闭时不落盘。新排队下载用任务元数据区分资源菜单与旧队列，实际开始记录与入队记录分开，以便分辨新请求与已有任务重新启动。

单 EXE 启动器从 0.1.41 起不再单独写 child-exit 日志；诊断开关与自选日志目录由 Qt 进程统一管理，历史版本规则保持兼容。
