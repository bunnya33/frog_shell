# 应用锁与收藏终端组

0.1.35，2026-11-11。沿用原生 Qt Widgets、Dracula/GitHub Light、应用缩放和现有终端/编辑/传输实现。

## 收藏终端组

默认打开收藏先验证目录，再定位资源管理并打开关联终端组。关联键包含服务器凭据身份、收藏稳定 ID 和规范化启动路径。反复打开只激活最近聚焦的活动终端；点击分屏正文也记录焦点顺序，不发送 cd，不重建组内对象。目录验证失败、身份更换、收藏移除、旧目录响应均不会错误重用。终端启动失败标记已结束，不把失败 PTY 当作活动终端。

组名跟随收藏别名（以纯文本展示）。组头「在组内新建终端」及拆分归属原组；全局 + 仍创建独立组。「在此处新建终端」是显式新增，与默认打开复用分开。移除收藏只解除关联，进程保留；最后一个终端关闭时清理关联。全组结束时保留输出历史，下一次打开创建一个新活动终端，后续复用该终端。手动终端名优先，普通终端可显示 shell · 目录末段；顶部单终端名称包含收藏归属。完整提示使用【启动目录】，不伪装当前工作目录。

## 应用锁操作

默认关闭。设置 → 安全 · 应用锁，启用输入两遍 6–128 字符密码；修改或关闭需校验当前密码。右上角锁按钮仅在启用后显示。设置重置保留应用锁。

启动时先读取独立安全记录；启用或记录损坏时只构造锁屏宿主，正确密码之前不构造连接仓库或主工作区，不读取 SSH 凭据、不连接服务器。`--demo` 也必须先解锁同一数据目录；`--help` 和 `--version` 可正常返回。

锁态由应用控制器统一管理。主窗、普通浮动编辑/终端窗及后续窗口均覆盖完全不透明的锁面；底层直接内容隐藏并禁用，窗口标题/可访问名称替换为通用锁定标题。锁中取消菜单、文件选择框、模态提示和未释放的拖拽；普通浮窗保留并在解锁后恢复内容。Esc、外部点击、窗口显示/最大化不解锁。密码输入禁止复制/剪切、上下文菜单、预测和记忆提示，临时输入提交后清除；KDF 在独立有界工作线程执行。

每次锁请求都推进操作 epoch，包括已锁状态收到新的锁屏事件。正在解锁的旧结果、锁前排队的信任/认证回调及模态返回必须通过代次校验。忙碌时不会覆盖已接受的解锁请求代次。取消启用/改密/关闭对话框使请求失效，写入前再检查请求 ID 和 epoch。

锁定不修改真实凭据/服务代次，不销毁文档或 PTY；已接受的后台传输继续。需要同名目标决策的传输暂停等待，解锁后重新显示提示，不自动覆盖或取消。新用户动作被阻断；新连接不在锁中启动。监测、PTY 输出/resize、任务完成和已接受的传输队列维护不被全局拦截。

锁中关闭窗口只隐藏，不弹出暴露草稿的确认。再次启动同数据目录实例会唤起原实例，仍保持锁。锁面提供「解锁后退出」：验证成功后走原有草稿/传输退出流程；只有启动锁宿主、尚无工作区时可直接退出。不会为快捷退出丢弃草稿或停止远端进程。

## 安全存储与边界

应用数据目录独立存放 `application-lock.json`，只含版本、enabled、KDF 类型、600000 次 PBKDF2-HMAC-SHA256、32 字节随机盐和 32 字节 verifier。不存明文或可逆密码；使用 OpenSSL 安全随机数、恒定时间比较，失败后按 1/2/4/8/16/30 秒限速；限速属于本次进程。密码计算临时字节完成后清理，无常驻明文密码缓存，不写日志/导出/剪贴板。

QSaveFile 禁止直接覆盖回退，临时文件写完后原子替换；POSIX 仅 owner 读写，Windows 设置当前用户独享的受保护 DACL。先提交有效记录，再创建永久非秘密 `application-lock.required` 标记。提交主记录前失败保持原设置且不创建标记；记录已提交但标记/权限确认失败如实提示实际状态，并使用已提交的新密码保护，不能假报关闭/启用成功。明确关闭保留 enabled:false 记录及标记。标记存在而记录缺失、enabled 与 verifier 不一致、格式损坏或不可读均 fail closed；不自动覆盖，也不能用界面重置解除。

同数据目录由 QLockFile 持有单实例锁，路径规范化后形成 IPC 名；QLocalServer 使用当前用户访问权限。第二实例只能唤起/显示，没有密码、命令或解锁协议。只持有目录锁的进程可清理陈旧 IPC 端点，不超时删除活实例锁文件。

这是应用操作保护，不是磁盘加密或操作系统级防篡改。直接修改/删除数据文件、使用旧版可执行文件或另选数据目录不属于此锁的 OS 级防护范围。忘记密码没有隐藏解锁入口；损坏记录应保留并从可信备份恢复。请继续使用操作系统账户、磁盘加密和目录权限保护数据。

## 系统通知与跨平台

Windows：隐藏原生通知窗口使用 WTSRegisterSessionNotification，接收 WTS_SESSION_LOCK、控制台/远程会话断连，以及 WM_POWERBROADCAST/PBT_APMSUSPEND。测试仅给本进程隐藏窗口发送模拟消息，绝不真正锁用户电脑。

macOS：CoreFoundation distributed notification 接入 com.apple.screenIsLocked；会话断连/休眠的覆盖不作保证。Linux：若构建提供 QtDBus，订阅兼容桌面 ScreenSaver ActiveChanged、login1 Lock/PrepareForSleep；桌面服务缺失会在设置中说明只能手动锁。没有以普通失焦冒充系统锁屏。macOS/Linux 代码路径须在对应系统完成构建和实机验收后才可宣称验证通过。
