# FrogShell

C++20 / Qt 6 Widgets 原生 SSH 工作区。按已确认的合并窗口原型实现，提供 Dracula 与 GitHub Light 两套主题。

当前开发版本为 **0.1.46**。真实 SSH、PTY、SFTP 与本地 TCP 端口转发已接入；完成与验证状态见各版本验证记录，不将开发版视为全部功能已验收的发布版。

## 运行

Windows 0.1.45 发布流程要求同时提供 `FrogShell-0.1.45-portable.exe` 单文件便携版、`FrogShell-0.1.45-setup.exe` 安装版以及包含两者的 `SHA256SUMS`。便携版可直接运行；安装版默认安装到当前用户的 `%LOCALAPPDATA%\Programs\FrogShell`。首次启动显示连接管理，不预置真实服务器。构建出的目录包也可从 `dist/FrogShell-0.1.45` 启动；打包脚本通过 `-Destination` 指定目标。

```powershell
.\dist\FrogShell-0.1.45\FrogShell.exe
# 离线界面预览，不连接服务器：
.\dist\FrogShell-0.1.45\FrogShell.exe --demo --data-dir .\build\preview-data
```

编辑区支持同排的两列、三列、四列及更多左右分屏；连续左右拆分始终保持同排，只在明确选择上下方向时建立上下布局；页签拖到中心合并、四边拆分、页签栏按位置排序，移空的组自动收起。新列只平分目标列原宽，保留其他列宽；新文件进入活动组。每组页签栏右侧同行提供分屏与合并图标，分屏主体默认向右，箭头菜单可选向右／向下；只在该组至少有两页时可用。点击哪组的按钮就操作哪组，全部合并归入点击组；编辑文件的移动与浮窗保留同一编辑器。没有额外“文件编辑”标题行。离线 demo 初始为四文件／三列，右列两页可继续拆成四列。详见 [编辑分组与面板设计](docs/RabbitShell-编辑分组与面板设计.md)。

终端光标默认闪烁块状，跟随远端的位置、显隐、闪烁和形状；左右／Home／End 等按键等待远端回传更新位置。Ctrl+C 在拖选或查找选区存在时复制并清除高亮（保留空格与缩进），无选区时返回最新输出并发送一次中断字节；单击不算选区，按住 Ctrl+C 不重复中断。Ctrl+Shift+C 保持纯复制，右键“中断命令”始终直接发送中断。详见 [终端光标与复制验证](docs/RabbitShell-终端光标与复制验证.md)。

0.1.6 修复终端内 Tab 被 Qt 焦点遍历提前处理的问题：聚焦终端时 Tab／Shift+Tab 分别发送 `09`／`ESC[Z`，焦点留在终端；连续 Tab 可重复发送，其他表单仍正常切换焦点。补全由远端 shell 决定，不在客户端枚举目录或生成候选。

进程完整表与侧栏前五项按 PID 增量刷新，保留仍在当前样本中的选中进程、当前单元格、排序、滚动和用户列宽；离开样本的 PID 只取消自身选择。两处统一为整体圆角卡片、连续表头和交替行底色，正文无网格，0.1.7 仅在表头增加列间短竖线；全部列可拖动调宽，完整表与侧栏独立保存并在下次打开恢复。身份仅基于 PID 与当前快照，不承诺识别所有 PID 复用。详见 [进程刷新与卡片验证](docs/RabbitShell-进程刷新与卡片验证.md)。

进程页只保留数据卡片，CPU／RSS 解释置于列标题悬停提示。网卡、认证与环境下拉框共用主题样式；终端拆分方向选择已移除，始终左右并排；原生列表优先在框下方展开，底部不足时向上，受屏幕范围约束。Esc 关闭不提交，重新展开定位到当前已选项。

文件删除按原操作路径只同步受影响的已加载目录，复用未变化树节点，保留其他分支的展开、选择与滚动；目录／符号链接类型变化会清理旧子树。右键目录新建固定到该目录，在树内输入文件或文件夹名：空名失焦取消，有名 Enter 或失焦提交，Esc 取消；非法名／已知同名保留修正，不覆盖已有文件。点击面包屑、双击目录或再次新建时先处理原草稿，Enter 与失焦不重复提交。

终端面板增加最大化／还原图标，仅扩展到右侧工作区域；左侧导航和页脚保留，编辑器对象及布局不销毁，还原原终端高度，最大化后隐藏会恢复编辑区。网卡按每个连接 profile.id 保存名称，只在用户主动选择时写入；网卡暂时缺失时使用可用回退但保留偏好，重现时恢复，名单未变不重建下拉项。

0.1.8 单终端直接关闭，无论忙闲均不确认、不探测进程；启动／关闭 probe、关联状态和专用检测模块已移除。整工作区／应用退出确认及编辑器未保存保护仍保留。总工具栏右侧显示当前终端图标和省略名称，完整名称见 tooltip；选中管理行提供拆分、垃圾桶关闭，键盘切行保留列表焦点。关闭当前终端优先选择同组相邻项，关闭其他终端保留活动项。终端内不再重复名称行，右键保留重命名并同步浮窗标题；不提供更改颜色和移入编辑区。终端独立浮窗与收回保持同一 PTY，收回到原终端组；文件编辑分屏和浮窗继续支持。

文件树有焦点时 Delete 与右键删除共用确认（默认取消）、父子去重及局部刷新；输入框、行内编辑、文件编辑器和终端的 Delete 不删除文件。资源管理底部提示块移除。路径框空白处左击进入编辑并全选当前路径，目录段左击直接导航；Enter 提交，Esc／失焦还原已提交路径，不自动导航未提交内容。无额外路径按钮或窗口级 Ctrl+L。

任务行保留当前文件已传／总量，增加实时速度，完成后保留平均速度。worker 按每次尝试实际成功的 SFTP payload 计数，目录跨子文件累计、跳过不计；有效耗时含枚举和原子提交，排除排队与 worker 暂停等待。实时为最近节流区间速度，暂停前后重置采样；重试从零统计。空文件／全部跳过显示 0 B/s，部分失败标“本次已传平均”，失败／取消不会冒充成功。详见 [0.1.8 验证记录](docs/RabbitShell-0.1.8验证记录.md)。

0.1.6 清理被替换的页签关闭按钮，复用高亮正则，查找替换面板改为首次使用时创建。隔离 25 轮开关文件后，关闭按钮不再累积，编辑器／文档／高亮器均销毁；Private Bytes 最终从基线 25.785 MiB 降至 24.344 MiB。这是同参数独立进程观测，不代表全部场景无泄漏或固定内存上限，详见 [0.1.6 验证与内存记录](docs/RabbitShell-0.1.6验证与内存记录.md)。

新建／编辑连接及登录弹窗可勾选“保存密码”（私钥认证显示“保存私钥口令”），默认不勾选。勾选后使用系统安全凭据库，重连和重启可自动读取；编辑已保存连接时密码留空保留原值，取消保存或删除连接会清理对应凭据。复制、导出不携带密码及保存偏好。运行时输入的凭据在认证成功后保存，存储失败会提示，本次会话仍可使用。

Windows 使用 Credential Manager，macOS 使用 Keychain，Linux 使用可选的 libsecret/Secret Service。不可用时不回退到明文文件；Linux 安装 `libsecret-1-dev`（Debian/Ubuntu）或 `libsecret-devel`（Fedora）后重新配置构建，并确保桌面密钥环可用、已解锁。Linux 请求支持约 15 秒取消期限。Windows 已实际验证；macOS/Linux 尚待对应系统构建和验收。详见 [保存密码设计](docs/RabbitShell-保存密码设计.md) 与 [验证记录](docs/RabbitShell-保存密码验证.md)。

连接配置、主机指纹和草稿位于 Qt 的应用数据目录；`--data-dir <path>` 可指定独立测试目录，普通连接 JSON 不含密码。普通 SSH 断开后重连不能恢复原来的进程。

## 构建

依赖：CMake ≥ 3.24、C++20 编译器、Qt ≥ 6.8（Core/Gui/Widgets/Network/Test）、OpenSSL 3。libssh2 1.11.1 和 libvterm 0.3.3 由 CMake 下载并核对 SHA-256。Qt 动态链接，不使用 Qt WebEngine、Chromium、Monaco 或 WebView。

Windows 使用 MSVC。此工作区已经在 `.tools/Qt` 安装了独立的 Qt 6.8.3 SDK 和 OpenSSL 开发包，不改变全局 PATH。

```powershell
.\scripts\build-windows.ps1
.\scripts\package-windows.ps1 -Destination .\dist\FrogShell-0.1.39
```

macOS / Linux：安装相应 Qt SDK 和 OpenSSL 开发包后：

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=/path/to/Qt
cmake --build build --parallel
ctest --test-dir build --output-on-failure
cmake --install build --prefix dist
```

核心界面、会话和文件操作使用跨平台接口；Windows 标题栏颜色集中在条件编译的平台适配层，不支持相关 DWM 属性时保留系统装饰，macOS/Linux 使用 Qt 的平台窗口外观。**0.1.11 的实测范围为 Windows offscreen、临时配置及隔离 loopback SSH fixture；未连接用户服务器、修改真实凭据或操作可见桌面。macOS/Linux 客户端需要对应系统构建与验收。0.1.7 的进程探针验证仅为历史记录，相关能力已移除。** 远端系统监控目前面向提供 `/proc`、`ps`、`df` 的 Linux。

`rabbitshell_terminal_tests` 使用 offscreen 私有剪贴板与临时配置，覆盖完整物理 Ctrl+C 按键序列、空白／反向／中文选择、查找选区、自动重复、光标纯移动／亮灭／远端属性与计时器生命周期，并输出两主题真实 Terminal 控件截图。本轮仅在 Windows 执行；macOS/Linux 未验收，loopback fixture 仅验证 PTY 连续性和字节路由，不执行真实 shell 或证明 SIGINT 行为。

`rabbitshell_process_tests` 通过离线 Workspace 的连续监控快照验证完整表与侧栏的 PID 重排、CPU/RSS 变化、item 复用、选择／current／排序／双向滚动／列宽保留、进程退出与空快照；输出两主题完整表及窄侧栏真实控件截图。

`rabbitshell_control_tests` 验证下拉框上下弹出、屏幕边缘／有限空间、靠后当前项、Esc 后重新展开、键盘／鼠标仅提交一次及父窗口移动关闭。`rabbitshell_memory_probe` 独立执行三轮预热与 25 轮实际编辑器生命周期，保存逐轮 Private Bytes、Working Set、句柄和对象计数；不加入常规 CTest，不进行强制内存 trim。0.1.6 内存结果保留为历史证据，本轮不重复压力审计。0.1.8 相关 CTest 6/6 通过：core 9、editor_groups 29、terminal 17、processes 8、controls 6、workspace 14；SSH/SFTP fixture 3 项及指定存活 PTY／未保存保护 fixture 5 项通过（均含 init/cleanup），0 failed／0 skipped。两主题生产 QWidget::grab 证据、复现命令和包验证见 [0.1.8 验证记录](docs/RabbitShell-0.1.8验证记录.md)。[0.1.7 验证记录](docs/RabbitShell-0.1.7验证记录.md) 保留当时结果，其关闭检测规则已由本版覆盖。

协议集成测试使用随机本机端口和独立临时目录，不执行系统 shell 命令，不连接真实服务器：

```sh
python -m pip install paramiko
python tests/run_integration.py build/Release/rabbitshell_session_tests.exe
python tests/run_integration.py build/Release/rabbitshell_credential_tests.exe
# Linux/macOS 的可执行文件通常位于 build/rabbitshell_session_tests
```

需要让测试进程找到 Qt 和 OpenSSL 动态库。未提供本机测试端口时，单独运行 `rabbitshell_session_tests` 会明确跳过网络测试；上述运行器会建立真实 SSH 测试端点。

Windows 内存采样：`scripts/measure-memory.ps1 -AppProcessId <PID>`。分别记录私有提交（Private Bytes）、私有工作集、总工作集和 CPU；私有工作集计数器不可用时为 null。三种内存口径不相加、不互相替代。

## 目录

- `src/core`：连接配置、后台 SSH/SFTP 会话和任务。
- `src/ui`：主窗口、工作区、原生终端、编辑器和主题。
- `prototype`：已确认的交互原型构建源。
- `docs`：功能依据、主题规范、实现记录及待办。
- `tests`：核心测试和本机协议测试。
- `third_party`：依赖版本、来源与许可证。

0.1.9 本轮新增文件图标名称匹配、矢量资源、1×／1.5×／2× 渲染、重命名／目录改名／分屏／浮窗主题切换检查；编辑分组 29 项、工作区 16 项及指定隔离 PTY／未保存流程 5 项均通过（含 init/cleanup）。早期全量运行的两项夹具失败与针对复测分别保留，最终证据见 [0.1.9 验证记录](docs/RabbitShell-0.1.9验证记录.md)。

## 单 EXE 启动版

只复制 `dist/FrogShell-0.1.39-portable.exe` 并双击即可启动，无需旁置 Qt 或构建工具。首次解到 `%LOCALAPPDATA%\RabbitShell\runtime\<payload hash>`，后续校验复用；为兼容旧版本保留内部目录名，默认沿用原配置，支持 `--demo`、`--version`、`--data-dir <绝对目录>`。本版验证见 [0.1.39 验证记录](docs/FrogShell-0.1.39验证记录.md) 及包外交付报告。旧目录和单 EXE 不回写；目录文档冻结后 pin inventory，再显式使用 `package-portable-windows.ps1 -Version 0.1.39 -Source ./dist/FrogShell-0.1.39 -Manifest <inventory>`。脚本仍保留历史 RabbitShell 包的参数及校验规则。诊断日志存于稳定的本地应用数据目录，设置显示实际路径；`--data-dir` 同时隔离日志，不写入临时解压 runtime。启动器仅尽力记录非零 ChildExit，不能凭退出码判定崩溃；捕获范围见诊断说明。

单 EXE 中终端清屏同样保留当前可见软行和原光标坐标，上方留空白；全屏/软行跨历史时禁用。遇到 Vim 等画面异常可从设置打开诊断日志目录提供日志，新增字段只有终端尺寸/光标/模式/滚动数值，不含终端正文；真实 Vim 问题仍待进一步确认。
